## 1. The catalog pipeline

### `scripts/regen_catalog.py` (389 lines)

- **What it fetches.** `scripts/regen_catalog.py:47` `URL = "https://models.dev/api.json"`, pulled with
  `urllib.request.urlopen(URL, timeout=60)` into a temp file
  (`scripts/regen_catalog.py:142-146`). Stdlib only; no retry, no proxy handling, no local-cache
  fallback. With an argv path it reads that file instead (`:140-141`).
- **Provider set.** 13 registries in the `PROVIDERS` table (`:52-87`): anthropic, openai, deepseek,
  google, xai, groq, moonshotai, zai, openrouter, mistral (M47), google-vertex (M48),
  amazon-bedrock (M49), github-copilot (M55). Order is both display order **and** the
  first-provider-wins dedupe priority (`:51`, `:233-236`).
- **Selection rules** (`select_rows`, `:157-258`):
  - `tool_call == true` (`:166-168`)
  - provider-specific exclusions: vertex keeps only `gemini-*` minus one preview (`:172-176`);
    bedrock drops `claude-opus-5`, `ai21.jamba*`, `mistral.mistral-7b-instruct-v0` (`:181-187`);
    copilot drops `*-picker` aliases (`:194-196`)
  - bedrock id normalisation: region prefix strip + version tail strip (`:205-210`)
  - `modalities.output == ["text"]` (`:211-213`) — image/TTS/embedding rows omitted
  - dated `-YYYYMMDD` suffix dropped (`:214-216`, `DATED_SUFFIX` `:89`)
  - `limit.context > 0` required (`:217-221`)
  - provider-qualified ids get `vertex/`, `bedrock/`, `github-copilot/` prefixes (`:227-232`)

## 4. Periodic updates — automation **exists**

`.github/workflows/catalog-drift.yml` (94 lines):

- Trigger: `schedule: cron '23 4 * * 1'` (Mondays 04:23 UTC) **plus** `workflow_dispatch` (`:19-23`).
- Steps: checkout → Rust toolchain (rustfmt only) → Python 3.12 → `python scripts/regen_catalog.py`
  (`:45-46`) → `cargo fmt -p epsilon-llm` (`:49`) → drift detection via
  `git diff --quiet crates/epsilon-llm/src/catalog/catalog_data.rs` (`:51-60`) → if changed, force-push
  branch `catalog-drift/latest` (`:62-70`) → open **or refresh** one PR against `main`
  (`:72-93`). It never pushes to main (`:6-7`, `:62-70`). No `gh` failure path if `gh` is missing, and
  no explicit step asserting `catalog_snapshot_date_matches_the_data` still passes after a refresh.
- The generic `ci.yml` runs `cargo test --workspace` on PRs (`.github/workflows/ci.yml:48-49`), so
  the drift PR is gated on the catalog pins.

So "periodic updates" is satisfied by CI. What is *not* automated is the hand-maintained
`CATALOG_SNAPSHOT_DATE`: the generator writes the new date into the data header only
(`regen_catalog.py:355-360`), so **the first refresh after any date change makes
`catalog_snapshot_date_matches_the_data` fail on the drift PR** until a human edits
`catalog.rs:33`. The workflow's own comment acknowledges red CI on drift PRs
(`catalog-drift.yml:9-11`).

## 5. Failure behaviour

### Generator (`scripts/regen_catalog.py`)

- **Unreachable models.dev:** `load_registry` is called first thing in `main` (`:349`), the
  `urlopen` exception propagates uncaught → Python traceback, exit code 1, and **`OUT.write_text`
  at `:379` is never reached**. The committed `catalog_data.rs` is therefore untouched. No retry,
  no timeout retry, no clean error message, no "keep the last good payload" path (the temp file
  `modelsdev.json` is written only after a successful download and is never re-read).
- **Malformed / schema-changed payload:** same — `json.loads` or `select_rows` raises/exits
  (`:254-257`) before the write.
- **Conclusion:** last known valid data is preserved **structurally**, not by a resilience
  mechanism. The only weakness is diagnostics (traceback instead of a one-line
  `FATAL: could not fetch models.dev: …`), which makes the CI failure harder to read than it needs
  to be.

### Workflow

A failed regen aborts the job at the "Regenerate the catalog" step; the diff/push/PR steps are
skipped, so nothing partial can be published. That is the correct behaviour. It does mean a models.dev
outage is indistinguishable in the log from a real catalog bug unless you read the traceback.

### Picker live fetch

`catalog::live_models` returns `Err(String)` for a bad endpoint, a missing key, a transport error,
a non-2xx status, and a bad payload (`catalog.rs:756-801`).
`App::record_live_result` (`epsilon-tui/src/app.rs:1492-1511`):

- `Ok(names)` → replaces/appends the provider's entry in `self.live_cache` (`:1501-1504`),
  invalidates the picker, marks the provider fetched (`:1505-1506`), announces the count.
- `Err(e)` → returns `Some("live listing failed: {e}")` and **leaves `live_cache` untouched**
  (`:1509`) — the bundled catalog rows and any previous good listing survive. That is the
  last-known-good preservation on the read path.

**But** the failure notice is not gated on `force`. The event loop pushes whatever
`record_live_result` returns (`epsilon-tui/src/app/event.rs:320-326`), so an auto-fetch failure
(offline, 401, rate limit) prints `live listing failed: …` into the transcript even though the arm's
own doc comment promises "Auto-fetch stays silent on failure" (`app.rs:1420-1421`). M306 silenced the
*no-credential* case only (`app.rs:1462-1469`).

## 6. Live-fetch path in the model picker — targeting and failure handling

- **Entry points:** `App::request_live(force)` (`app.rs:1422-1488`). Called with `false` from
  `/models` (`commands.rs:758`), from `app.model.select` (`keys.rs:2281`) and from the picker-open
  path (`keys.rs:1989`); with `true` from `app.live.refresh` = `Ctrl+G` (`keys.rs:2161-2165`).
- **Target = the row the cursor is on, not the whole catalog.** `request_live` resolves
  `self.picker_provider` (stage 2), else the highlighted stage-1 provider row
  (`app.rs:1429-1436`), then fetches that one provider. This is explicitly the known divergence from
  pi: `docs/STATUS.md:3266-3272` ("Target | the whole catalogue, once, at startup | whichever row the
  cursor is on, on every picker open") and `:3280-3282` ("Still open … the auto-fetch on
  picker-open targets a cursor row rather than the whole catalogue"). M20's original intent
  ("M17 passed a model id here, which `catalog::live_models` always rejected") is fixed — since
  `app.rs:1416` a provider name is passed.
- **Guards before any fetch:** fetcher present (else, only if `force`, a notice that the build has no
  `real` feature, `:1423-1428`); `live_listing_available(provider)` (`:1440-1447`);
  `resolve_api_key(provider).is_none()` → silent unless `force` (`:1462-1469`);
  already-fetched providers skipped unless `force` (`:1470-1472`); one fetch in flight
  (`:1473-1475`).
- **Merge:** live ids that are *not already in the catalog* become synthetic `is_live` rows under
  their own provider group, deduped case-insensitively — stage 2
  (`picker.rs:731-738`, test `stage2_merges_live_ids_for_its_provider_only` `:1666-1694`) and the
  global list (`picker.rs:284-306`, test `live_rows_surface_only_unknown_ids_under_their_group`
  `:1643-1661`). Known ids are never duplicated. There is no timeout anywhere in this path (pi bounds
  its refresh at 15 s, `STATUS.md:3270`), and no staleness/timestamp recorded per live listing.
- **Failure handling:** as above — `live_cache` untouched (last known good preserved), an error
  notice is printed for both force and auto paths.

## 8. Smallest correct addition per gap (ranked)

1. **Add capability fields to `ModelInfo` and populate them from models.dev.** Two fields first:
   `reasoning: bool` (and optionally `reasoning_options: &'static [..]`), plus
   `supports_vision: bool` from `modalities.input` containing image. Script side: read `m["reasoning"]`
   and `m["modalities"]["input"]` in `select_rows`, emit them in `emit_row`. Then migrate
   `reasoning_effort_for` (`openai_compat.rs:259-294`) and the mistral branch
   (`mistral.rs:85-99`) to read the row instead of the id substring. Smallest correct version:
   one `bool` per row + a picker glyph.
2. **Add `status: &'static str` (or `deprecated: bool`) to `ModelInfo`,** read from
   `m.get("status")`, and have the picker badge deprecated rows (the `is_unavailable` strike pattern
   at `picker.rs:749-762` / P-260 is the precedent to copy). A generator-side *filter* is the wrong
   first move — keep showing them, mark them.
3. **Widen pricing.** `micro_usd` already exists; add reads for `context_over_200k` (an input
   multiplier with a threshold) and `tiers` (a list), and store
   `long_context_input_cost_micro_per_mtok` + threshold — or, more honestly, add a
   `pricing_tiers` note and *report* unpriced-token buckets in the cost panel rather than invent a
   number. Audio/reasoning-token keys are only relevant to audio-style models the selector already
   drops.
4. **User-facing refresh.** A `/catalog refresh` argument (or Ctrl+G-equivalent command) that runs
   the same live-listing path across *all* credentialed providers into `live_cache` in one pass —
   no file writes, no cargo, works from the running TUI. This closes "manual refresh" without
   touching the committed store.
5. **Make the date derived, not transcribed.** Extend `regen_catalog.py` to rewrite the
   `CATALOG_SNAPSHOT_DATE` line in `catalog.rs` (a single-line regex replace next to the existing
   `OUT.write_text`), keeping `catalog_snapshot_date_matches_the_data` as the guard. The drift PR
   then goes green by construction.
6. **Staleness in `/catalog`.** Add a pure `catalog_snapshot_age_days()` (parse the const, compare
   to `std::time::SystemTime::now()`), and have the arm append "…(N days old)" plus a stronger line
   past a threshold (e.g. 30 days). Testable with the existing frame-witness pattern.
7. **Gate the auto-fetch failure notice on `force`** in `record_live_result` (pass `force` through,
   or return `None` for `Err` when the fetch was automatic) so the transcript stays quiet for
  housekeeping, matching `app.rs:1420-1421` and `STATUS.md:3272-3274`.
8. **Long-context honesty in the cost panel.** If a model publishes `context_over_200k` pricing, the
   cost report should say the estimate uses the base rate above the threshold instead of pricing it
   at the base rate silently.
9. **Optional pi parity for the refresh target** (whole catalogue at startup, 15 s timeout, honour an
   `EPSILON_OFFLINE`-style env) plus recording a per-provider last-success timestamp for the live
   listing. Only after 1–3 land; it is a UX change to a shipped behaviour (`STATUS.md:3280-3282`).
10. **Generator diagnostics:** wrap the `urlopen` in `try/except` and `sys.exit(f"FATAL: could not
    fetch {URL}: {e}")` so the drift job's log names the cause; same for the malformed-JSON path.
11. Delete the stray spaces in the `/catalog` notice string (`commands.rs:2237`) and, in the frame
    test, assert the unsqueezed fragment too so the regression can't come back.
12. Change `catalog_snapshot_date_matches_the_data` to parse the header date and assert equality
    with the constant rather than `contains`.
13. Add the missing providers (`mistral`, `google-vertex`, `amazon-bedrock`, `github-copilot`) to
    `listing_endpoint` if and when those providers expose a listing; otherwise leave `None`

## Bottom line

The catalog pipeline is complete and, for what it does, well pinned: a committed generated table,
six integrity tests, a weekly drift workflow that opens a PR, and a `/catalog` command that prints
the snapshot date and the table's real size. What criterion 5 asks for and the tree does **not**
carry is per-model **capability/reasoning/deprecation metadata** (one `supports_tools` bit today,
