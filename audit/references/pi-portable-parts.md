# pi → Epsilon: portable parts

Source mined: `references/pi-0.84.2/` (TypeScript monorepo: `packages/{agent,ai,coding-agent,tui,protocol,session-backends,server,client,telemetry}`).
Target: the Rust workspace in `crates/` (11 crates). Read-only audit; every anchor below was opened and read.
Prior art deliberately excluded (already in Epsilon): two-level loop, steering/follow-up queues, fail-all-on-truncation (`epsilon-core/src/lib.rs:964-969`), per-tool `execution_mode` with batch-level sequential degradation (`epsilon-contracts/src/tool.rs:16`, `epsilon-core/src/exec.rs:200-201`), `ToolUpdateSink`/`ToolPartial` types, per-path file mutation queue (`epsilon-tools/src/mutation.rs`), compaction amend-mode, overflow recovery (`epsilon-core/src/lib.rs:928-941`), skills catalog, JSONL tree sessions + leases + crash repair, subagents, OAuth, catalog.

## Verdict

Epsilon's *skeleton* is at or past pi: the loop, queue semantics, truncation-failure rule, session trees, and tool decomposition all match, and pi's own `AgentHarness` class is largely unimplemented stubs (`packages/agent/src/harness/agent-harness.ts:355-508` returns `HarnessNotImplemented` for `prompt`, `compact`, `navigateTree`, `resume`, `watch`; `create()` throws on restore at `:350-352`), so several pi "features" are design intent rather than shipped behavior. Where pi is meaningfully ahead is the *context layer* (usage-anchored token accounting, split-turn-safe compaction, file-operation ledgers, branch summaries), *liveness* (throttled streaming tool output; Epsilon's bash buffers everything until exit), and *recovery rigor* (deferred/suspended operations, typed corruption codes, fail-closed restore) plus the resource/hook surface (prompt templates, active-tool sets, per-turn hooks). Epsilon is ahead on permissions and OS confinement — pi's README states plainly that it ships no permission system, and its extensions run in-process.

## Detail

### 1. Usage-anchored context accounting
pi walks the message list backwards for the last assistant message with a *valid* usage block (skipping `aborted`/`error` and zero-token turns), takes `totalTokens || input+output+cacheRead+cacheWrite` as ground truth, then estimates only the messages *after* that index at chars/4 (`estimateTokens`, with a flat 4800-char cost per image). Result shape: `{tokens, usageTokens, trailingTokens, lastUsageIndex}`. Compaction fires at `contextTokens > contextWindow - reserveTokens` (`compaction.ts:247-250`), reserve default 16384. In Rust: extend `epsilon-core/src/compact.rs` with `ContextEstimate { usage_tokens, trailing_tokens, last_usage_index }` and have `compaction_due()` (`epsilon-core/src/lib.rs:1078-1088`) prefer it, falling back to `estimate_messages` only when no usage exists. Keep the heuristic for the tail; never re-estimate history the provider already counted.

### 2. Throttled streaming tool output
`executeShellWithCapture` sanitizes each chunk (drop control chars except `\t\n\r`, strip `\r`), tracks `totalBytes`/`completedLines`/`currentLineBytes`, keeps a rolling tail trimmed on a UTF-8 boundary (`shell-output.ts:43-49, 114-144`), and exposes `onChunk(text, getProgress)` where progress = current tail + truncation + spill path. `bash.ts` coalesces updates at 100 ms (`BASH_UPDATE_THROTTLE_MS`, `scheduleOutputUpdate`) and pushes `{content, details:{truncation, fullOutputPath}}` through `onUpdate`. In Rust: `epsilon-tools/src/shell.rs` must move off `cmd.output()` to a streaming reader that feeds `ctx.on_update(ToolPartial::…)` on a ~100 ms cadence, with the sandbox path exposing stdout/stderr pipes instead of a buffered struct. `epsilon-contracts` and `exec.rs` already relay `ToolExecutionUpdate` to the TUI.

### 3. Split-turn-safe compaction
`findValidCutPoints` admits only user/assistant/bashExecution/custom/branchSummary/compactionSummary entries — never a `toolResult` (`compaction.ts:312-344`). `findCutPoint` walks back accumulating tokens until `keepRecentTokens` is reached, snaps to the nearest valid cut point, then walks backwards to a message/compaction boundary. If the cut lands inside a turn, `findTurnStartIndex` (`:347-361`) finds the owning user message and the range `[turnStartIndex, firstKeptEntryIndex)` is summarized *separately* with `TURN_PREFIX_SUMMARIZATION_PROMPT` ("Original Request / Early Progress / Context for Suffix", max 50% of reserve) and concatenated as `history + "\n\n---\n\n**Turn Context (split turn):**" + prefix` (`:689-765`). In Rust: add `plan_cut(entries, start, end, keep_tokens) -> CutPoint { first_kept, turn_start, is_split }` to `epsilon-core/src/compact.rs`, use it instead of the raw token split at `epsilon-core/src/lib.rs:1103-1118`, and emit a second summary call for the prefix.

### 4. File-operation ledger
`extractFileOpsFromMessage` inspects assistant tool calls for `arguments.path` and buckets by tool name: `read`→read, `write`→written, `edit`→edited (`utils.ts:24-51`). `computeFileLists` subtracts modified from read so a file appears once, sorted. `extractFileOperations` (`compaction.ts:44-67`) seeds the accumulator from the *previous* compaction entry's stored `details.{readFiles,modifiedFiles}` and then adds the newly summarized messages, so the ledger survives repeated compactions. `formatFileOperations` appends `<read-files>`/`<modified-files>` blocks to the summary text, and the same arrays are persisted on the compaction entry. In Rust: `epsilon-core/src/compact.rs` should compute the ledger from `AssistantMessage::tool_calls()` args, merge it with `EntryKind::Compaction.details` (currently only `{"pruned_tool_results": n}` at `lib.rs:1176`), and append the two blocks — no new session entry fields needed.

### 5. Cache-miss detection and waste pricing
`detectMiss` compares a message's prompt size (`input + cacheRead + cacheWrite`) with the previous request's, computes `missedTokens = min(prev.promptTokens, promptTokens) - cacheRead`, ignores anything under 1024 tokens (breakpoint granularity noise), and prices the miss as `missed * max(0, paidRate - cacheReadRate)` using the message's *own* cost breakdown (`cache-stats.ts:56-90`). Zero-cache turns only count when cache activity was seen before (`reportedCache` stickiness), so providers that never report caching produce no false alarms. `idleMs` is compared against the 5-minute Anthropic TTL to name the likely cause, and `scan` clears `prev` across compaction/branch-summary entries while deliberately *not* exempting model switches (`:112-131`). In Rust: this is a pure function over the session branch — put it in `epsilon-session` or `epsilon-core`, surface a one-line transcript notice plus a cumulative total in `epsilon-tui/src/footer.rs`.

### 6. Deferred / suspended tool execution
A tool may return a deferred outcome; the assistant message is persisted with `stopReason: "deferred"` and a `deferred` handle, and the run ends as `{kind: "suspended", deferred}` (`agent-harness.ts:93`). Session records carry `write_deferred` with a provisioned target entry (`session/types.ts:185`), so the eventual result is written by a later fetch, not by the run that asked for it. Recovery distinguishes `reason: "crash" | "deferred"` (`:145`) and offers `fetch_deferred`/`cancel_deferred` actions carrying provider+id (`:194`). The reducer treats the deferred message as a live handle (`reducer.ts:597-603`), a corruption reason exists for a deferred message without one (`:277-280`), and `sessionEntryToContextMessages` omits deferred assistant messages from the model view (`session/context.ts:72`) so a half-made request never reaches the provider. In Rust: `epsilon-contracts` needs a `DeferredHandle` on the assistant message, a `SessionEntry` variant for the handed-off write, `repair_on_open` must recognise the state as *suspended* (not dangling) and `epsilon-core` must expose a resume entry point.

### 7. Truncation contract
Two directions, both with a rich result: `truncateHead` (read) and `truncateTail` (shell), each returning `{content, truncated, truncatedBy: lines|bytes, totalLines, totalBytes, outputLines, outputBytes, lastLinePartial, firstLineExceedsLimit, maxLines, maxBytes}` (2000 lines / 50 KB defaults, `truncate.ts:11-13`). Head truncation never emits a partial line; if a single line exceeds the byte cap it returns empty content with `firstLineExceedsLimit: true`, and `read.ts:119-121` converts that into an actionable message (`Use bash: sed -n 'Np' file | head -c 51200`). Byte-capped reads say `Showing lines X-Y of N (50KB limit). Use offset=N+1 to continue.`; shell truncation says `Showing lines X-Y of N. Full output: <temp path>`, and when a single line was partially kept it says so and reports the line's size. `truncateLine` caps grep matches at 500 chars with a `... [truncated]` suffix. In Rust: split `epsilon-tools/src/util.rs::truncate_output` into `truncate_head`/`truncate_tail` returning a struct with these fields, use it in `files.rs` (read) and `shell.rs`, and render the *suggested* next `offset`.

### 8. Branch summarization
Before moving the leaf, pi collects the entries from the old leaf back to the deepest common ancestor with the target path (`collectEntriesForBranchSummary`, `branch-summarization.ts:82-111`). `prepareBranchEntries` walks newest-first under a `contextWindow - reserveTokens` budget, always keeping nested compaction/branch summaries if under 90% of budget, and accumulates file ops (including from nested summaries' `details`) (`:132-171`). The prompt is a fixed 7-section template; the result is prefixed with `"The user explored a different conversation branch before returning here.\nSummary of that exploration:"` so the model reads it as exploration, not current work, and is persisted as a `branch_summary` entry with `maxTokens: 2048`. In Rust: `epsilon-session` already has tree walks for fork/timeline; add `collect_branch_entries(store, old_leaf, target)` plus a summary call in `epsilon-core`, and a `SessionEntry` variant or `details`-tagged entry the model view renders as that preamble.

### 9. Prompt templates
Directory roots are scanned one level for `*.md` children (sorted, non-recursive), frontmatter supplies `description`/`argument-hint` and falls back to the first 60 chars of body; missing paths and non-markdown are skipped, and read/parse failures become warning diagnostics with stable codes (`prompt-templates.ts:4-16, 30-62, 95-166`). `parseCommandArgs` does shell-style single/double quoting; `substituteArgs` handles `$1`, `$@`, `$ARGUMENTS`, `${@:N}` and `${@:N:L}` (`:218-257`). `loadSourcedPromptTemplates` attaches caller-defined provenance to each template *and* each diagnostic so the loader stays policy-free. Skills use the same loader shape and render invocations as `<skill name="…" location="…">\nReferences are relative to <dir>.\n\n<body>\n</skill>` (`skills.ts:38-41`) — the "References are relative to" line is what makes bundled reference files usable. In Rust: a `prompt_templates` module next to `epsilon-core/src/skills.rs` reusing its frontmatter parser, plus TUI slash-command completion.

### 10. Edit fuzzy chain, Unicode-aware
Exact match first; on failure both content and `oldText` go through `normalizeForFuzzyMatch`: NFKC, per-line trailing-whitespace strip, smart single/double quotes → ASCII, `U+2010-2015`/`U+2212` dashes → `-`, `U+00A0`, `U+2002-200A`, `U+202F`, `U+205F`, `U+3000` spaces → `' '` (`edit-diff.ts:30-51`). When a fuzzy match is used, `applyReplacementsPreservingUnchangedLines` widens each replacement to the base lines it touches, groups overlapping ranges, rewrites only those lines from the *normalized* base, and copies every untouched line from the *original* bytes (`:128-169`) — so a fuzzy edit cannot silently reformat the file. Errors are specific: empty `oldText`, N occurrences (with "provide more context"), overlapping edits (naming both indexes), and "replacement produced identical content" (`:254-290, 342-360`). In Rust: extend `edit_match.rs` with a `normalize_for_fuzzy_match` stage plus a line-span splice over the original content.

### 11. Fail-closed record-log validation
`validateRecordLog` runs before reduction and throws `RecordLogCorruption` with one of 12 machine-readable reasons: `multiple_open_operations`, `unknown_operation`, `record_after_finish`, `non_consecutive_attempt`, `invalid_compaction_reason`, `queue_after_abort`, `invalid_queue_cancellation`, `inconsistent_step`, `tool_call_mismatch`, `duplicate_tool_invocation`, `provisioned_entry_mismatch`, `invalid_deferred_handle` (`reducer.ts:22-44`). The invariant that matters: these are states the single-writer protocol *cannot* produce, so restoring must refuse rather than repair (`:311-390`). Checks include attempt numbering continuity per operation and per step, that each tool start matches the assistant entry's tool call by index *and* id *and* name, that a tool invocation is not duplicated, and that a provisioned entry's payload deep-equals its intent (parent/seq/timestamp ignored, `:139-152`). In Rust: split `epsilon-session/src/repair.rs` into "recoverable prefix" (today's behaviour: synthesize missing tool results) and a `SessionCorruption { reason, message }` enum that makes load fail closed with a stable code, mirroring Epsilon's existing error taxonomy style.

### 12. Skills loading, take two
Discovery is recursive: a directory containing `SKILL.md` *is* a skill and is not descended into further (`skills.ts:137-149`); otherwise children are visited alphabetically, skipping dot-dirs and `node_modules`, and root-level `.md` files load as skills at the top level only (`:151-172`). `.gitignore`, `.ignore` and `.fdignore` are honored per directory with the directory prefix applied to each pattern (negation and escaping preserved) (`:177-241`). Name is frontmatter or parent directory, validated for ≤64 chars, lowercase/digits/hyphens, no leading/trailing/double hyphen, and must match the parent dir; description is required and ≤1024 chars; validity problems emit `invalid_metadata` warnings but do not abort the scan, and a skill *without* a description is dropped (`:243-310`). In Rust: `epsilon-core/src/skills.rs` should recurse, respect ignore files (or at least document skipping them), and return `Vec<(Skill, Vec<SkillDiagnostic>)>` so `/skills` can show what was skipped and why.

### 13. Active tool set
The session persists `active_tools_change { activeToolNames }` entries (`session/types.ts:40-41`); the effective set is derived from the latest such entry on the branch (`session/context.ts:28-42`), so it survives resume and fork. The loop sends only active tools to the provider, and a tool result may carry `addedToolNames` (`agent-loop.ts:787`) which the harness applies to the active set — an escape hatch for tools that unlock others (e.g. a "load extension" tool). `setActiveTools`/`getActiveTools` are part of the lane API (`agent-harness.ts:299-300, 434-439`). In Rust: `epsilon-core` already persists `TurnEnd`/`Compaction` entries, so add an `EntryKind::ActiveTools { names }` (session schema change), derive the tool list per turn in the loop, and keep the `task` tool's toolset overrides as today's special case.

### 14. User bash as a message
`BashExecutionMessage` carries `command`, `output`, `exitCode`, `cancelled`, `truncated`, optional `fullOutputPath`, and `excludeFromContext?: boolean` (`messages.ts:23-32`), so a human's `!cmd` lands in the transcript as its own message role and can be kept out of the model view. `executeBashWithOperations` (used for local and remote/SSH execution) streams through the same sanitizer, spills to a temp file past the byte cap, and keeps a rolling buffer (`bash-executor.ts:45-156`). The compaction code treats `bashExecution` as a turn boundary (`compaction.ts:320-327`), and extensions observe it via a `user_bash` event (`coding-agent/src/core/extensions/types.ts:814`). In Rust: a new `Message::BashExecution` variant in `epsilon-contracts`, a `/!`-style TUI path that records it, and a `exclude_from_context` flag the prompt builder honours.

### 15. Per-turn hooks and a replayable action log
pi names 11 harness hook points — `before_run`, `before_resume`, `before_run_end`, `transform_context`, `before_request`, `before_payload`, `after_response`, `before_tool`, `after_tool`, `before_compaction`, `before_navigation` (`agent-harness.ts:198-209`) — and encodes every side effect as a labelled action (`append_entry`, `apply_pending_write`, `stream_assistant {step, attempt}`, `execute_tool`, `fetch_deferred`, `hook`, `sleep`) with `peekAction()`/`executeAction()` for stepping (`:182-196`), plus `runWhenIdle`/`waitForIdle` for queued work. The loop itself offers `prepareNextTurn` (returning a context snapshot plus a new model/thinking level mid-run) and `shouldStopAfterTurn` (`agent-loop.ts:226-257`), and `transformContext` runs once per provider call (`:288-292`). In Rust: the honest scope is the hook *taxonomy* on top of Epsilon's existing event bus plus a `prepare_next_turn` callback for mid-run model/thinking switches; an action-log replay engine is a separate project and pi's own version is unproven (see "do not port").

### 16. Images: resize before attach
`createReadTool` takes an injected `imageProcessor` and an `autoResizeImages` flag (default true); when set, the processor returns `{data, mimeType, hints}` and the hints are prepended to the text block so the model learns the image was resized (`read.ts:35-42, 58-63`). BMP without a processor is refused with an explicit reason rather than shipped as undecodable bytes. The coding-agent side has `utils/image-resize.ts`, `image-resize-worker.ts`, `image-process.ts`, and `exif-orientation.ts` (directory listing; not read). In Rust: `epsilon-tools/src/image.rs` should gain a max-dimension/byte budget, downscale (and optionally strip EXIF by re-encoding) before base64, and return a hint string ("image resized 4000×3000 → 1568×1176"); failing that, cap by bytes and say so.

### 17. Backend conformance suite
`packages/agent/src/harness/session/testing/conformance.ts` (1016 lines) exports a fixture-factory-driven battery: the caller supplies a backend fixture and the suite asserts the repo contract — entry append/id/parent semantics, operation records, compaction/branch entries, error codes — using plain asserts (`:1-55` shows the helpers and the `SessionBackendFixtureFactory`/`SessionBackendConformanceCase` types). Rust analogue: an `epsilon-session` integration test that takes a constructor for "a store" (JSONL now, memory or SQLite later) and asserts the same behaviours through the public API, so a backend swap or schema migration is caught by a contract rather than by ad-hoc tests.

### 18. Telemetry contract
pi's telemetry package defines vendor-neutral schemas, a memory sink, a noop sink, and a conformance suite (`packages/telemetry/src/index.ts`, `testing/conformance.ts`), and the agent emits semantically named attributes — including `pi.ai.deferred`, operation kinds `stream|fetch_deferred|cancel_deferred|generate_images`, and enumerations of stop reasons and run outcomes (`harness/telemetry.ts:52-90, 393`). Epsilon's event bus is consumed live and dropped. In Rust: a `telemetry` sink trait with a JSONL writer (one line per turn: model, tokens, cache read/write, cost, stop reason, tool count/duration), wired from the existing `AgentEvent` stream in `epsilon-core`, plus a conformance-style test for the sink. This is also the natural home for the cache waste from candidate 5.

## Deliberately do not port

- **pi's in-process JS extension API** (`packages/coding-agent/src/core/extensions/types.ts:1193-1227`, 1728 lines of handler surface): Epsilon's process-isolated extension host is a deliberately stronger boundary; pi's README concedes it ships no permission system, and in-process extensions can rewrite tool arguments and provider payloads.
- **npm package manager / self-installing packages** (`core/package-manager.ts`, 2677 lines; `package-manager-cli.ts`, 889): a supply-chain and reproducibility liability against the "exact-pinned deps, offline tests, one static binary" rule.
- **The `AgentHarness` class surface as-is** (`agent-harness.ts:355-508`): ~30 methods that `Promise.reject(HarnessNotImplemented)`, and `create()` refuses to restore an existing session (`:350-352`). Copy the *ideas* (suspended runs, hooks, lane API), not the contract.
- **Multi-lane orchestration** (`AgentLane`, `createLane`, `lanes()`, `watch`, `agent-harness.ts:271-303`): Epsilon already covers the real use cases with subagents (background/resume/per-child model) plus separate session files; a lane fleet multiplies concurrency bug surface for no demonstrated need.
- **Terminal graphics / image protocols** (`packages/tui/src/terminal-image.ts`, 657 lines, plus Kitty negotiation): Epsilon documented graphics as deferred (`epsilon-tui/src/state.rs:41-47`) and it conflicts with the offline-test goal; an escape-sequence emulator would have to be maintained too.
- **CBOR binary protocol alongside NDJSON** (`packages/protocol/src/cbor/`, `framing.ts`): a second codec for the editor surface duplicates the schema, and the NDJSON rpc mode already ships.
- **pi's model-data generator** (`packages/ai/scripts/generate-models.ts`, 2943 lines): Epsilon's `scripts/regen_catalog.py` + models.dev feed already produces a drift-checked catalog; two generators would fight.
- **Third-party OAuth client IDs** (`packages/ai/src/auth/oauth/*.ts`, from the tree listing, not opened): Epsilon's explicit "never ship another project's registration" rule stands.
- **`/share`-style gist upload of full transcripts** (pi's `utils/git.ts` / interactive export path): outbound data egress on a transcript containing source code and possibly secrets deserves opt-in per-run, not a convenience command.
