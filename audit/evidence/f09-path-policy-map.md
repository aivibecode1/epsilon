# F09 — path-policy implementation seams and bounded design

**Status:** read-only source review and proposed acceptance plan; F09 remains open.
**Snapshot:** HEAD `80b32eb1e76a2fa9084ad1e69b300c0800186cf4`, after source-closure integration `b57c8bf`. Citations below refer to the inspected working-tree files. A targeted `git diff --name-only` returned no differences for the eleven mapped core/contracts/tools source files. Broad unrelated owner modifications remain; none were changed or staged by this review.
**Evidence level:** source trace, not runtime verification. No builds, tests, exploit reproduction, network calls, source edits, or commits were performed. Earlier 740-test evidence is baseline context, not evidence that F09 is fixed (`agents/memory/next-hardening.md:3–17`). This report is the only created artifact; parent owns memory/index/documentation follow-up.

## Decision in brief

Replace the lexical tuple with one fallible resolved-path policy, and consume its identity consistently at authorization, scheduling, native execution, observations, and checkpoint boundaries. Include existing-parent resolution for creation. Merely changing `paths.rs` leaves the independent gate normalizer, implicit search roots, descendant traversal, and checkpoint replay outside the policy.

The bounded result should be described as **resolved-path validation for a non-adversarial/stable filesystem namespace, not race-resistant confinement**. Fail closed on unsupported path syntax, unresolved existing components, or identity drift detected between preparation and execution. If the required mode promises resistance to concurrent namespace replacement, this slice cannot provide it: refuse that mode until a separately reviewed native handle-relative/access backend exists. This is the explicit stop condition in `audit/04-roadmap.md:69–78` and `audit/02-defect-ledger.md:132–140`.

## 2. Minimum coherent design slice (proposal, not implemented)

### A. One resolution contract, distinct display and policy identity

Keep implementation in core's existing path module; keep contracts limited to data/traits rather than moving filesystem behavior there (`AGENTS.md:69–80`). Replace the tuple contract with a fallible result carrying:

- resolved absolute workspace root;
- resolved absolute target / resource key;
- workspace-relative identity when contained;
- requested spelling for display and preservation of existing path-specific denials;
- intent (existing file, existing directory, or create beneath an existing directory) and a resolution outcome distinguishing missing suffix from errors.

A canonical path is a **namespace identity**, not a unique file-object identifier. Do not name it an inode/file-ID guarantee. Use path-native identity internally, never a lossy display string as a lock key. Produce one explicit permission-subject rendering (including separator convention) from validated components. If current string-only policy/checkpoint formats cannot faithfully represent a name, refuse it in this bounded slice rather than silently merge names.

Resolve an existing root first; refuse an invalid/inaccessible root. Existing inputs must resolve as the requested object type. For creation, permit only genuinely absent normal components under a resolved, existing directory; distinguish not-found from access-denied, malformed, dangling-link, non-directory, loop, and unsupported-reparse failures. Never convert arbitrary canonicalization failure into “new file.” Do not lexically erase parent traversal before understanding link semantics; the simplest bounded policy is to refuse ambiguous link-plus-parent traversal and unsupported forms rather than guess the OS destination.

Retain strict resolved-workspace containment for native tools in this slice. An explicitly selected linked workspace root may be supported as the trust anchor if owner policy permits it. A link within that root resolving elsewhere is not silently authorized by ordinary file permission. If legitimate external linked trees are later supported, design an explicit additional-root policy first.

### B. Preparation and execution must agree

Build path identity before permission evaluation, touched-path recording and planning for native path-bearing operations. Reuse it for subjects/resource keys; convey it to native execution through a narrowly reviewed data seam (for example prepared context metadata). A shared helper independently called everywhere is a useful implementation step, but alone does not prove the authorized path equals the path used later.

Revalidate after interactive approval and after acquiring a mutation lock. If resolved identity changed, refuse/reprepare rather than using approval or a lock for a different resource. This detects some drift; it does **not** close the final check-to-access race. Direct tool invocation outside core must still enforce the same policy, with no fallback to raw paths. Reads and edits require existing objects; writes may use create intent. Scheduler planning for a missing future target can use the resolved parent plus validated suffix; execution must resolve again after earlier same-batch creation.

Permission compatibility needs explicit tests: retain original tool denial, then any external constraint. Do not discard a deny tied to the requested alias just because a canonical target has another name. Evaluate applicable requested and resolved policy subjects conservatively (denial wins) and bind any reusable approval to the resolved resource. Keep labels/raw arguments for user understanding, not as authority. Do not broaden current session-memory glob semantics incidentally.

### C. Traversal is its own seam

For the minimum bounded behavior, resolve an explicitly requested in-workspace linked root only under the selected link policy, then **do not descend through discovered link/reparse entries**. Use non-following entry classification where the platform actually supports it; unknown Windows reparse kinds are unsupported, not ordinary directories. Skip or refuse visibly according to the operation's contract.

If descendant links are later followed, each destination needs containment, secret-policy checks, cycle control and scheduler accounting. A single directory-prefix resource key is not sufficient when traversal can reach a different in-workspace subtree through an alias. Refusing such descendant traversal avoids expanding this slice into multi-resource planning. Apply equivalent rules to attachment listings and grep content opens; do not assume a validated starting directory validates its descendants.

### D. Thread identity through state and storage

Mutation queue and read-log should consume the prepared/resolved key, not normalize separately or fall back to process cwd. Preserve F02's separate opaque observation owners and sibling invalidation.

Checkpoint capture should serialize the relative form of that same identity, under the same resolved root. Validate the checkpoint store directory, ledger, blob directory and referenced blob locations as well as the user's target. Blob identifiers should match the store's existing generated-name grammar, never arbitrary paths (`crates/epsilon-tools/src/checkpoint.rs:332–356`). Restore must reject invalid/absolute/parent-bearing stored paths and unsupported aliases, resolve existing-parent creation targets, and lock the same target used for restore. Revalidate old entries rather than trusting old lexical serialization; ambiguity should produce a clear refusal, not an automatic migration or destructive cleanup. Do not claim F15 closure from this change.

## 3. Windows cases that must be explicitly specified

These are proposed native-platform acceptance categories, not measured claims about this machine. Avoid hand-written global lowercasing or prefix stripping as a substitute for filesystem semantics.

| Case | Bounded policy/acceptance expectation |
|---|---|
| Ordinary relative, absolute drive-qualified paths; mixed separators; dot components | Equivalent supported names yield one internal identity and one rendered relative subject. Containment compares components, not textual prefixes; sibling roots with a common textual prefix stay distinct. |
| Drive-relative and root-relative-without-drive forms | Refuse ambiguous forms rather than depend on process/per-drive cwd. An absolute workspace must not inherit unrelated process drive state. |
| Different drives and UNC shares | Either explicitly support a canonical UNC workspace and same-share descendants, or return an unsupported capability error. Different roots/shares are outside. No network access is needed for parser fixtures; actual UNC support needs separate approved native evidence. |
| Verbatim/extended-length versus ordinary paths | Canonicalization may introduce a different representation. Root and target must use compatible representations. Do not strip prefixes blindly. Explicitly reject device namespaces and unsupported volume forms. |
| Case variants / case-sensitive directories | Test on the actual filesystem mode. Do not merge distinct objects in a case-sensitive directory by lowercasing; do not assume `PathBuf` textual equality proves alias equivalence on a case-insensitive volume. Use a proven identity strategy or refuse/report unsupported equivalence. |
| Junctions, symlinks, other reparse points | Cover explicit root alias, allowed internal alias, and refusal decisions using inert fixtures. Do not equate every reparse point with a symlink. If kind/target cannot be reliably classified, fail closed. Do not enable privileges or change security configuration to make tests pass. |
| Nonexistent leaf and several missing parents | Resolved existing directory plus normal absent suffix; permission, scheduler, capture and creation share the same identity before/after creation. A dangling link or inaccessible ancestor is not a missing-parent case. |
| Reserved device names, alternate streams, trailing-dot/space aliases, invalid/control/NUL input | Explicitly reject unsupported namespace spellings before I/O. Never let parser-dependent names acquire a different permission subject than their I/O meaning. |
| Short/long-name aliases, hard links, mount/volume aliases | Do not assert canonicalization deduplicates all object aliases. Add native evidence or restrict support; document residual identity limits. Hard links are not made unique by canonical path normalization on either Windows or Linux. |
| Attachment drive colon versus numeric range; non-ASCII/non-round-trippable names | Drive-qualified reference with optional numeric line suffix has an explicit grammar. Unsupported stream syntax is refused. Internal identity stays path-native; persisted/policy representation is lossless or the operation is refused. |

## 4. Unsupported guarantees and honest wording

- No race-resistant open/create/replace/delete claim: resolution, approval, lock acquisition, metadata, checkpoint capture, parent creation and final host filesystem operations are separate events in the current paths (`files.rs:284–314,461–499`; `checkpoint.rs:261–279`). Revalidation reduces detectable drift but leaves a final replacement interval.
- A process-global path mutex orders participating harness mutations only; it does not bind namespace components, exclude external writers, lock across separate harness processes, or serialize aliases not represented by the same key (`mutation.rs:14–38`; `read_log.rs:3–14`).
- No unique-object/hard-link deduplication, metadata-snapshot atomicity, content freshness against same-size/same-time external changes, or checkpoint durability claim follows from canonicalization (`read_log.rs:124–139,202–228`; `checkpoint.rs:223–235`).
- No shell sandbox enclosure of native reads/writes: native tools call host `std::fs` directly. The sandbox's bubblewrap arguments configure a spawned command and expose `/` read-only (`crates/epsilon-safety/src/sandbox.rs:310–348`); read-only is not read confidentiality. Windows Job Objects are not a general file/network boundary, as already recorded in `audit/02-defect-ledger.md:140`.
- A future race-resistant design needs a separately reviewed access layer using appropriate directory/file handles and no-follow/reparse-aware operations across the full operation, plus native tests. Do not imply `canonicalize`, `symlink_metadata`, or checking again immediately before open provides that layer.

Suggested current product wording: “Native file operations currently use lexical workspace checks and are not sandboxed filesystem access. Resolved-path hardening is pending. Do not rely on these checks to confine access in a workspace containing untrusted links or concurrent namespace changes.” After implementation and native evidence, replace “lexical” with the precise supported resolved-path policy, but retain the race and platform limitations.

## 5. Proposed inert acceptance tests — not executed

Use an in-memory resolver/metadata abstraction for refusal/error/drift branches and disposable native temporary directories containing only harmless generated text for ordinary identity behavior. No real secrets, host out-of-workspace reads/writes, adversarial link swaps, shell payloads, paid APIs, or network fixtures are required. Link capability tests must report explicit unsupported/skipped status with reasons; a skip is not native closure.

| ID | Owning seam | Proposed assertion |
|---|---|---|
| P01 | core paths | Table-driven ordinary relative/absolute/dot paths and sibling-root cases; success returns consistent root/relative/absolute identity; invalid syntax returns typed refusal. Windows-only spellings are tested on Windows or against a clearly modeled parser, not inferred from Unix parsing. |
| P02 | core paths create intent | Existing target, missing leaf and multiple absent parents map consistently; mocked inaccessible, non-directory, dangling, loop and unsupported-reparse outcomes never fall back to lexical acceptance. Resolver itself creates nothing. |
| P03 | core exec + safety | Faux recording tool/provider and recording gate see matching permission identity and resource key; denied/invalid inputs produce zero tool invocations. Preserve original tool denial before external authorization and preserve requested-alias denials. No shell execution. |
| P04 | core planner + tools keys | Read/write/edit alias spellings group together; directory reads conflict with descendant writes; find declares a directory key; failed resolution is blocked rather than an independent parallel `None` key. Two unrelated supported resources remain independently schedulable. |
| P05 | tools read/write/edit + read-log | Harmless temp file: same observer reads supported spelling A and edits spelling B; another observer's successful mutation invalidates A by the same key. Preserve partial-read/full-overwrite rules and both single/batch edit behavior. Prefer deterministic barriers/recorded order over sleeps. |
| P06 | traversal/search/listing | Mock directory entries include ordinary files, denied/unknown link kinds and resolution errors. | P07 | attachments | Text, range, directory and image-read entrypoints share path-policy decisions. Mock requested/resolved sensitive names are refused before content retrieval. | P08 | checkpoint capture/replay | Harmless temp file/new-file lifecycle serializes the same relative identity used by mutation. Crafted in-memory ledger entries with invalid target/blob grammar are rejected before any filesystem callback. Mock denied store/parent locations prevent capture/replay/eviction access. Existing valid entries remain readable; no automatic rewrite. |
| P09 | native platform capability | Ordinary temp-root identity, supported in-root alias equivalence and new-path identity run separately on native Windows/Linux. Use only approved benign alias fixtures wholly within the temp root. Unknown reparse behavior or unavailable privilege yields an explicit limitation, never a universal support claim. |
| P10 | deterministic identity drift | Inject resolver results A at preparation and B at execution; require refusal/repreparation before I/O. This tests the drift-detection contract only, not an exploit or proof that every replacement race is closed. |
| P11 | Windows namespace policy | Parser/error fixtures cover drive-relative/root-relative, UNC/verbatim/device categories, stream syntax, reserved/trailing forms, case modes and non-round-trippable names. Unsupported forms fail before file access; claimed supported equivalences need native evidence. |
| P12 | regression boundaries | Faux full-loop plan-mode tests still deny write/edit/shell as appropriate; successful supported read/edit paths preserve F01/F02 behavior. Keep checkpoint durability/conflict tests tracked under F15 rather than marking those findings closed. |

**Exit recommendation:** implementation only after the owner selects supported link/reparse and Windows identity policy. Close the bounded identity subtask only with all consumers updated and native evidence for supported cases; retain an explicit open limitation for race-resistant access. The present report supplies seams and acceptance intent, not a security certification or an executed green result.
