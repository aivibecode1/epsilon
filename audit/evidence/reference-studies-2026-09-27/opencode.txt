# opencode 1.18.31 — Architecture & Capabilities

**Scope note:** I read only the reference tree. Root is a Bun/TypeScript monorepo, `"packageManager": "bun@1.3.14"` (`package.json:7`), 36 workspace packages (`package.json:25-32`).

## 1. Top-level structure

| Package | TS files / lines | Owns |
|---|---|---|
| `packages/opencode` | 678 / 180k | **The shipped CLI + v1 agent runtime.** yargs entrypoint, `session/`, `tool/`, `provider/`, `permission/`, `lsp/`, `mcp/`, `server/` (v1 HTTP) |
| `packages/core` | 479 / 68k | Shared kernel: SQLite/Drizzle DB, git, session-v2, v2 permissions, `pty`, `filesystem`, `skill`, `oauth`, `config` |
| `packages/llm` | 105 / 21k | **Hand-rolled native provider stack** — 5 protocol decoders + SSE/WS/HTTP/Bedrock transports |
| `packages/tui` | 204 / 32k | SolidJS + OpenTUI terminal UI |
| `packages/app` | 596 / 171k | SolidStart web/desktop client, 20+ i18n locales |
| `packages/schema` | 71 / 3.6k | Effect Schema definitions (v1 + v2) — the wire/DB contract |
| `packages/server` | 29 / 1.7k | New v2 Effect-HttpApi server |
| `packages/sdk` | 44 / 30k | Generated JS client (from `openapi.json`) |
| `packages/desktop` | 137 / 9.4k | Tauri/Electron shell |
| `packages/console`, `packages/stats` | | Hosted SaaS console + usage analytics (SST/Cloudflare Workers) |
| `packages/cli` | 21 / 890 | A **separate** binary named `lildax` (`packages/cli/package.json:8`), daemon-oriented. Not the `opencode` binary. |

**Two generations coexist in one process.** This is the single most important structural fact:
- v1 runtime: `packages/opencode/src/session/prompt.ts:1081` (`runLoop`), `packages/opencode/src/session/processor.ts:641` (`process`).
- v2 runtime: `packages/core/src/session/runner/llm.ts` (20.9k), reachable via `packages/core/src/location-services.ts:35` → `packages/server/src/routes.ts:26-52`.
- `packages/opencode/src/cli/cmd/serve.ts:14` loads **only the v1 server**, but that server mounts both APIs: `packages/opencode/src/server/routes/instance/httpapi/server.ts:74,102,104,105` import `Api`/`handlers`/`locationLayer` from `@opencode-ai/server`. Two HTTP APIs, one port.

`AGENTS.md:151-161` is a v2-session-core design memo; `AGENTS.md:157` explicitly forbids bridging v2 through `SessionPrompt.loop`.

**Runtime seams Rust must re-implement:** Bun-specific `imports` maps for `sqlite`/`pty`/`fff` (`packages/core/package.json:25-41`), Bun + Node SQLite drivers, `@lydell/node-pty` (a native patch, `package.json:18` postinstall), `@parcel/watcher`, and the Effect runtime itself (Layers/Scopes/Fibers/Stream/Deferred/Schema) which is load-bearing throughout.

## 2. The agent loop

`SessionPrompt.runLoop` — `packages/opencode/src/session/prompt.ts:1081-1339`. A plain `while (true)` in an Effect generator. The core abstraction is **"re-read durable history, decide, emit one assistant message, let the DB decide the next iteration"** — not an in-memory transcript.

```ts
1088|        while (true) {
1089|          yield* status.set(sessionID, { type: "busy" })
1092|          let msgs = yield* MessageV2.filterCompactedEffect(sessionID)...
1096|          const { user: lastUser, assistant: lastAssistant, finished: lastFinished, tasks } = MessageV2.latest(msgs)
1106|          const hasToolCalls = lastAssistantMsg?.parts.some(
1108|              (part) => part.type === "tool" && !part.metadata?.providerExecuted && !isOrphanedInterruptedTool(part)) ?? false
1111|          if (lastAssistant?.finish && !["tool-calls","unknown"].includes(lastAssistant.finish)
1114|              && !hasToolCalls && lastAssistant.parentID === lastUser.id) { ...; break }
```

The explicit guard at `1103-1105` is worth quoting: *"Some providers return `stop` even when the assistant message contains tool calls. Keep the loop running so tool results can be sent back to the model."*

**Streaming:** `processor.process` (`packages/opencode/src/session/processor.ts:641-660`) consumes a typed event `Stream` and normalizes AI-SDK `fullStream` parts into `LLMEvent`:
```ts
654|            const stream = llm.stream(streamInput)
656|            yield* stream.pipe(
657|              Stream.tap((event) => handleEvent(event)),
658|              Stream.takeUntil(() => ctx.needsCompaction),
659|              Stream.runDrain,
660|            )
```
The event vocabulary is a 12-variant protocol-agnostic union in `packages/llm/src/schema/events.ts:78-198`: `step-start`, `text-start/delta/end`, `reasoning-start/delta/end`, `tool-input-start/delta/end`, `tool-call`, `tool-result`, `tool-error`, `step-finish`, `finish`, provider-error. This is the cleanest abstraction in the repo and the best thing for a Rust port to copy.

**Tool calls:** the AI SDK owns dispatch; the processor persists a `ToolPart` per call in `pending`→`running`→`completed|error` (`processor.ts:123`, `processor.ts:598-605`).

**Retries:** `packages/opencode/src/session/retry.ts`. Constants at `:26-31` (2s initial, ×2, 25% jitter, 30s cap without headers, 5 attempts). Honors `retry-after-ms` / `retry-after` (seconds or HTTP-date) at `:51-71`. 5xx always retried even when the SDK doesn't mark it (`:92-98`). **Retryability is regex-based on error text** — 7 patterns at `:33-41` matching things like `/overloaded|service unavailable|internal error/`. That's a design smell worth not copying.

**Cancellation:** no AbortController plumbing in the loop itself. `SessionRunState` holds one `Runner` per session (`packages/opencode/src/session/run-state.ts:38,52-69`); `cancel` walks the session tree and kills background jobs transitively (`run-state.ts:77-86`, `111-143`), then `runner.cancel` interrupts the Effect fiber. `Effect.onInterrupt` finalizers stamp `interrupted: true` on in-flight tools (`processor.ts:598-605`) and set a synthetic `AbortedError` on the assistant message (`prompt.ts:1203-1211`). Shutdown is forceful: `process.exit()` in a `finally` (`index.ts:136-141`) because MCP subprocesses ignore SIGTERM.

**Step budget:** `agent.steps ?? Infinity` (`prompt.ts:1178`). On the last step it injects a fake assistant message — `prompt.ts:1281` appends `MAX_STEPS_PROMPT` — and force-disables tools. The prompt text is `packages/core/src/session/runner/max-steps.ts:1-16` ("CRITICAL - MAXIMUM STEPS REACHED … Tools are disabled until next user input").

**Compaction:** auto-triggered on token overflow (`prompt.ts:1161-1168`) with a 20k-token reserve buffer (`packages/opencode/src/session/overflow.ts:8-20`); can also be requested by the model as a task (`prompt.ts:1149-1159`).

## 3. Tool system

**Definition** — `packages/opencode/src/tool/tool.ts:55-65`:
```ts
export interface Def<Parameters extends Schema.Decoder<unknown> = ..., M extends Metadata = ...> {
  id: string
  description: string
  parameters: Parameters
  jsonSchema?: JSONSchema7
  execute(args, ctx: Context): Effect.Effect<ExecuteResult<M>>
  formatValidationError?(error: unknown): string
}
```
`Tool.define(id, init)` (`:151-169`) wraps `execute` to (a) compile the decoder **once per init** — `const decode = Schema.decodeUnknownEffect(toolInfo.parameters)` (`:111`, with a comment explaining the hoisting), and (b) auto-apply output truncation (`:130-144`). Every tool therefore gets bounding and tracing for free via `Effect.withSpan("Tool.execute", {attributes: {"tool.name", "session.id", ...}})` (`:145`).

**Built-ins** — 16 registered at `packages/opencode/src/tool/registry.ts:209-249`: `invalid, shell, read, glob, grep, edit, write, task, fetch, todo, search, skill, patch, question, lsp, plan`, plus experimental `execute` (code mode). Conditional exposure:
- `question` only for `app|cli|desktop` clients (`registry.ts:207`)
- `lsp` only under `experimentalLspTool` (`:247`)
- `plan` only under `experimentalPlanMode && client === "cli"` (`:248`)
- **Patch-vs-edit is model-sniffed** (`:297-300`): `usePatch = modelID.includes("gpt-") && !oss && !gpt-4`; `apply_patch` is exposed *instead of* `edit`/`write`.
- `websearch` only for `opencode`/`opencode-go` providers or Exa/Parallel flags (`:58-65`, `:293`)

**Plugin/dir tools** — auto-discovered by globbing `{tool,tools}/*.{js,ts}` in config directories (`registry.ts:183-197`), then dynamic-`import`ed.

**Schema discipline** — the notable bit is the **dual-schema bridge for Zod plugin args** (`registry.ts:125-137`):
```ts
130|          const args = def.args ?? {}
132|          const allZod = entries.every((entry) => isZodType(entry[1]))
134|          const jsonSchema = zodParams ? zodJsonSchema(zodParams) : legacyJsonSchema(entries)
136|            ? Schema.declare<unknown>((u): u is unknown => zodParams.safeParse(u).success)
```
with a dated comment (`:128-129`) that pre-1.14.49 the code was `z.object(def.args)` and Zod silently tolerated `undefined` (#27451, #27630). Runtime validation uses Effect `Schema`; the LLM sees JSON Schema. Model-specific schema surgery happens in `SessionTools.resolve` via `ProviderTransform.schema(...)` (`packages/opencode/src/session/tools.ts:98`).

`tool.definition` is a plugin hook that can rewrite description/params per-call (`registry.ts:318-322`).

**Argument errors** are a typed class whose `message` getter is the model-facing prose — `tool.ts:24-34`:
> `The ${this.tool} tool was called with invalid arguments: ${this.detail}.\nPlease rewrite the input so it satisfies the expected schema.`

**Output bounding** — `packages/opencode/src/tool/truncate.ts`. `MAX_LINES = 2000`, `MAX_BYTES = 50 * 1024` (`:14-15`), overridable via `tool_output.{max_lines,max_bytes}` (`:75-83`). Over-limit output is **spilled to a file** and replaced with a preview + hint (`:124-141`). The hint is agent-aware — if a task tool is available it tells the model to delegate to `explore` rather than read the file itself (`:129-130`). Retention is 7 days with a 1-hourly janitor (`:12`, `:143-148`).

## 4. Session / persistence

**One SQLite file:** `packages/core/src/database/database.ts:53` → `join(Global.Path.data, "opencode.db")`, channel-suffixed for non-release builds (`:54`). XDG paths in `packages/core/src/global.ts:10-29`. Access via Drizzle ORM over `bun:sqlite` or `node:sqlite` behind one interface (`packages/core/src/database/sqlite.bun.ts:47`, `sqlite.node.ts`).

**Full schema:** `packages/core/src/database/schema.gen.ts:4-274`. Tables: `workspace, data_migration, account_state, account, control_account, credential, event_sequence, event, permission, project_directory, project, message, part, session_context_epoch, session_input, session_message, session, todo, session_share`.

**History data structure** — conversation is **two tables, message + part, each with a JSON `data` blob**:
```sql
128|        CREATE TABLE `message` (`id` text PRIMARY KEY, `session_id` text NOT NULL, ... `data` text NOT NULL, ...)
138|        CREATE TABLE `part`   (`id` text PRIMARY KEY, `message_id` text NOT NULL, `session_id` text NOT NULL, ... `data` text NOT NULL, ...)
```
Parts are a 12-member discriminated union — `packages/schema/src/v1/session.ts:357-370`: `TextPart, SubtaskPart, ReasoningPart, FilePart, ToolPart, StepStartPart, StepFinishPart, SnapshotPart, PatchPart, AgentPart, RetryPart, CompactionPart`. Assistant errors are an 8-member union (`:385-394`) including `ContextOverflowError`, `ContentFilterError`, `StructuredOutputError`.

**Branching — this is where opencode is weaker than expected.** There is *no* conversation tree or DAG. Three separate mechanisms:

1. **Session nesting** = subagents only. `session.parent_id` (`schema.gen.ts:186`). Used by the `task` tool, not by the user.
2. **Fork = full copy, not shared nodes.** `packages/opencode/src/session/session.ts:691-732`:
```ts
703|      const idMap = new Map<string, MessageID>()
704|      const target = input.messageID ? msgs.findIndex((msg) => msg.info.id === input.messageID) : msgs.length
706|      for (const msg of msgs.slice(0, target < 0 ? msgs.length : target)) {
707|        const newID = MessageID.ascending()
708|        idMap.set(msg.info.id, newID)
```
Every message and part is re-inserted with fresh ULIDs. No node sharing → forking a large session duplicates every row. Titles get a counter suffix (`getForkedTitle`, `session.ts:161-169`).
3. **Revert/undo** = git-based filesystem snapshots + a staged boundary. `packages/core/src/session/revert.ts`. Staged diffs are computed by walking assistant messages after a boundary and mapping files→snapshot trees (`revert.ts:27-58`); `stage`/`clear`/`commit` are the three states (`:60`, `:98`, `:113`). Snapshots are **real git objects** via `git write-tree` with a `GIT_INDEX_FILE` override — `packages/core/src/git.ts:531` and `:649` — not stash.

**Restart/recovery** — the v1 loop is restart-safe *by construction*: it re-reads the DB and resumes from the last assistant `finish` (`prompt.ts:1092-1130`). The v2 design is stricter and explicitly says so — `AGENTS.md:158`: *"post-crash continuation recovery requires a separate explicit design before it may retry provider work."* v2's durable inbox is `session_input` with `admitted_seq`/`promoted_seq`/`delivery` (`schema.gen.ts:158-168`) plus `session_context_epoch` (`:149-156`) and an event log with per-aggregate `seq` + `owner_id` for replay claims (`schema.gen.ts:73-88`).

**Legacy path still present:** `packages/opencode/src/storage/storage.ts:63-65` writes `path.join(dir, ...key) + ".json"`, and `:81-110` is a migration that walks the old `storage/session/message/*/*.json` tree into the DB. So there was a JSON-file era; SQLite is now canonical.

## 5. Permission system — the important part

**Three levels, two schemas.** v1 (`packages/schema/src/v1/permission.ts:16-24`): `{permission, pattern, action}` where action ∈ `allow|deny|ask`. v2 (`packages/schema/src/permission.ts:58-64`): `{action, resource, effect}` — renamed fields, same semantics. Both default-match with `*`.

**Evaluation is last-match-wins over a flattened ruleset** — `packages/opencode/src/permission/index.ts:28-38`:
```ts
29|    rulesets.flat()
30|      .findLast((rule) => Wildcard.match(permission, rule.permission) && Wildcard.match(pattern, rule.pattern)) ?? {
31|      action: "ask", permission, pattern: "*" }
```
Fail-closed default: no matching rule ⇒ `ask`. v2 is identical (`packages/core/src/permission.ts:76-86`).

**Config shape** — `packages/core/src/v1/config/permission.ts:17-36` enumerates the first-class keys: `read, edit, glob, grep, list, bash, task, external_directory, todowrite, question, webfetch, websearch, lsp, doom_loop, skill` + a `Record` catch-all. Each value is either an `Action` or `Record<pattern, Action>`; `~` and `$HOME` are expanded into absolute globs (`packages/opencode/src/permission/index.ts:178-184`).

**Defaults — and this is the headline** (`packages/opencode/src/agent/agent.ts:119-136`):
```ts
119|        const defaults = Permission.fromConfig({
120|          "*": "allow",
121|          doom_loop: "ask",
122|          external_directory: { "*": "ask", ...whitelistedDirs },
126|          question: "deny",
127|          plan_enter: "deny",
128|          plan_exit: "deny",
130|          read: { "*": "allow", "*.env": "ask", "*.env.*": "ask", "*.env.example": "allow" },
```
**Everything is allowed by default, including `bash`.** The only read gate is `.env` files (comment at `:129` notes it mirrors GitHub's gitignore `Node.gitignore` pattern). The `plan` agent inverts this — `edit: {"*": "deny", ".opencode/plans/*.md": "allow"}` (`agent.ts:171-175`) — and `explore` is `"*": "deny"` plus a read/grep/glob/bash allowlist (`:200-210`).

**What is actually enforced: nothing below the process.** I searched the whole tree for `landlock|seccomp|LD_PRELOAD|bubblewrap|bwrap|nsjail|AppArmor|pledge_unveil|sandbox-exec|seatbelt|chroot|unshare|clone3|SANDBOX`. The only hit in production code is a *deletion* — `packages/desktop/src/main/server.ts:218`: `if (process.platform === "linux") delete env.LD_PRELOAD`. There is **no Landlock, no seccomp, no syscall filtering, no container, no namespace isolation.** The shell tool spawns via `cross-spawn` (`packages/core/src/cross-spawn-spawner.ts`). A Rust port wanting real containment gets to *improve* on this — the enforcement surface is purely:

1. **In-process gate before side effects.** Each tool calls `ctx.ask({permission, patterns, always, metadata})` — 15 call sites. E.g. `read.ts:255-258` uses `patterns: [path.relative(worktree, filepath)]`; `edit.ts:102-105` shows the diff in metadata; `shell.ts:270-273` scans for out-of-tree dirs and asks `external_directory`.
2. **Worktree containment check** — `packages/opencode/src/project/instance-context.ts:18-24`:
```ts
19|  if (FSUtil.contains(ctx.directory, filepath)) return true
22|  if (ctx.worktree === "/") return false
23|  return FSUtil.contains(ctx.worktree, filepath)
```
The `/` guard is a real bug-avoidance note: non-git projects set worktree to `/`, which would match every absolute path and silently disable the permission.
3. **Tool hiding** — a `deny` with `pattern: "*"` removes the tool from the model's tool list entirely, it isn't just blocked at call time (`permission/index.ts:204-219`, applied at `session/tools.ts:87`).

**Approval flow.** `ask` publishes an event and blocks on a `Deferred` (`permission/index.ts:98-106`). Pending requests live in an **in-memory** `Map<ID, {info, deferred}>` (`:50`, `:99`) — so v1 "always" grants **die on restart**. The UI literally says so: `packages/opencode/src/cli/cmd/run/permission.shared.ts:128` — *"This will allow `{permission}` until OpenCode is restarted."*

Replies are `once | always | reject` (`packages/schema/src/v1/permission.ts:38`). Two nice touches:
- **Reject cascades**: rejecting one request fails every other pending request in the same session (`permission/index.ts:129-138`), so the model isn't left blocked on a stale prompt.
- **Always retro-resolves**: after saving a pattern, already-pending requests that the new rule would allow are auto-succeeded (`:153-166`). Same in v2, which additionally **persists** grants — `packages/core/src/permission/saved.ts:54-69` writes to the `permission` table with `onConflictDoNothing`, scoped by `projectID`.
- Reject-with-feedback produces `CorrectedError` carrying the user's message (`packages/core/src/v1/permission.ts:13-19`), so the model gets told *why*.

**Headless escape hatches** — `packages/opencode/src/cli/cmd/run.ts:242-256`. `--auto` is documented "dangerous!"; `--yolo` and `--dangerously-skip-permissions` are **hidden** flags that do the same thing: `const auto = args.auto || args.yolo || args["dangerously-skip-permissions"]` (`:274`). Three names, one behaviour, two undocumented.

**Also in the tree but weakly wired:** `packages/core/src/policy.ts` is a second, parallel `allow|deny` rule engine (no `ask`) with a `fallback` parameter (`:36-42`) — 49 lines, referenced by nothing outside itself in the search I ran. Looks like scaffolding for a future split of hard policy from interactive approval.

## 6. Provider abstraction

**Three layers.**

1. **Catalog** — data-driven from `models.dev` (`packages/core/src/models-dev.ts`, 266 lines; `Flag.OPENCODE_MODELS_URL` / `_PATH` at `flag.ts:45-46`). Provides model IDs, limits, and pricing.
2. **Factory registry** — a static map of npm package → dynamic import, `packages/opencode/src/provider/provider.ts:113-139`, 25 providers: `amazon-bedrock` (+`/mantle`), `anthropic`, `azure`, `google`, `google-vertex` (+`/anthropic`), `openai`, `openai-compatible`, `openrouter`, `xai`, `mistral`, `groq`, `deepinfra`, `cerebras`, `cohere`, `gateway`, `togetherai`, `perplexity`, `vercel`, `alibaba`, `gitlab-ai-provider`, `github-copilot` (redirected to a local shim at `core/src/github-copilot/copilot-provider.ts`), `venice`. Model → SDK instance is per-model `getModel()` (`:374-377`), with Bedrock cross-region-prefix handling.
3. **Two runtimes, with an opt-in seam.** The live path is AI SDK `streamText(...)` (`packages/opencode/src/session/llm.ts:280`). The alternative is `@opencode-ai/llm` — a from-scratch stack with 5 protocol decoders (`packages/llm/src/protocols/openai-responses.ts` 1022, `anthropic-messages.ts` 855, `bedrock-converse.ts` 674, `gemini.ts` 512, `openai-chat.ts` 506) and 4 transports (`route/transport/websocket.ts`, `http.ts`). It is gated behind `flags.experimentalNativeLlm` and **falls back to AI SDK** with a logged reason (`session/llm.ts:226-269`). This is a genuine in-progress migration, not dead code — but for a Rust port the AI SDK path is the one with production reality behind it.

**Streaming** is normalized either way into the `LLMEvent` union (§2). `experimental_repairToolCall` repairs malformed tool calls by lowercasing the name or rewriting input as `{tool, error}` (`llm.ts:296-309`). OTel tracing is per-turn and session-tagged via a Proxy that injects `session.id` into every span (`llm.ts:208-222`).

**Usage & cost** — `packages/opencode/src/session/session.ts:338-405`. Two design decisions worth stealing:
- **Cache tokens are always subtracted** because AI SDK v6 normalized `inputTokens` to *include* cache across all providers (comment at `:361-363`, code at `:364`). Provider-specific fallbacks are chained for `cacheWriteInputTokens` across anthropic/vertex/bedrock/venice metadata keys (`:346-359`).
- **Context-tiered pricing** (`:380-386`): pick the highest `tier.size` below current context tokens, falling back to `experimentalOver200K` past 200k.
- Copilot returns an authoritative `totalNanoAiu` which overrides the computation entirely (`:387-391`).
- Reasoning tokens are charged at the output rate with an explicit `TODO: update models.dev to have better pricing model` (`:398-400`).

The v2 `Usage` schema carries a stronger contract, documented at `packages/llm/src/schema/events.ts:7-50`: inclusive totals *and* a non-overlapping breakdown, with the invariant `nonCached + cacheRead + cacheWrite = input` and `reasoning ≤ output`, and per-field `Math.max(0,…)` clamping "eliminating the underflow class of bug" (`:25-33`). The v1 `getUsage` above is the older, subtraction-based version.

## What a Rust port should take, and what to skip

**Take:** the `LLMEvent` 12-variant union and its Usage invariant (`packages/llm/src/schema/events.ts:7-50`) — it is the best-designed contract in the repo. The DB-first agent loop shape (`prompt.ts:1088-1139`), which makes crash recovery a free consequence rather than a feature. `MAX_STEPS_PROMPT` tool-disabling on the final step (`max-steps.ts`). Output spill-to-file with agent-aware hints (`truncate.ts:124-141`). The "finish ≠ tool-calls" provider quirk guard (`prompt.ts:1103-1105`).

**Improve on:** permissions default to `* : allow` including unrestricted `bash` (`agent.ts:119-136`) with zero OS-level enforcement — a Rust port can ship real Landlock/seccomp containment, and should default `bash` to `ask`. Forking duplicates every row (`session.ts:691-732`); a DAG with shared nodes is strictly better. Regex-based retry classification (`retry.ts:33-41`) will misfire; typed error classes already exist and should be used. `Permission.evaluate` allocates a new object and flattens the whole ruleset on every call (`permission.ts:76-86`) — fine at this scale, but it is on the hot path for every tool call.

**Do not copy:** the Effect runtime dependency, the v1/v2 duplicate implementations, the Bun/Node conditional-import matrix, and the three-hidden-flags-one-behaviour permission bypass.
