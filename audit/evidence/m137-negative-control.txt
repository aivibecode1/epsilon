M137 NEGATIVE CONTROL — the early return restored, the truncation reproduced
=========================================================================

Defect under test
-----------------
F03. `WireStream::ingest` drained complete lines out of `line_buf` but `return`ed
from inside the loop after the first line that produced an event. Everything after
it stayed in `line_buf`, and `next()` never re-checked `line_buf` before awaiting
the next network chunk. A provider that delivered a whole short response in one
TCP chunk therefore had every frame after the first silently dropped, and because
the body then ended cleanly the harness reported the truncated answer as a SUCCESS.

Why a control at all
--------------------
The new tests could not have existed before this milestone: `WireStream` held a
concrete `reqwest::Response`, so no fixture could put more than one SSE frame in a
single chunk without a real socket. M137 added the seam (`WireStream::inner` is now
a boxed byte stream) and the tests with it. A test that is new alongside its fix
proves nothing on its own, so the pre-fix behaviour was reproduced explicitly.

The control
-----------
One insertion in `ingest`, immediately after `self.queued.extend(batch)`:

    // CONTROL (M137 negative control): queue the batch, then stop reading
    // this chunk -- exactly the pre-fix shape, where the remaining
    // complete lines stayed in `line_buf` and `next()` awaited the network.
    self.queued.extend(batch);
    if !self.queued.is_empty() {
        return self.queued.pop_front();
    }

This is the pre-fix shape precisely: the batch is queued and the first event is
returned, but the line loop stops, so the remaining complete lines in this chunk
are never read.

Command
-------
    export CARGO_TARGET_DIR="C:/Users/Hp/AppData/Local/Temp/eps-m137-target"
    export CARGO_BUILD_JOBS=1
    cargo test -p epsilon-llm --features real --lib http_stream

(`--features real` is required, and this is itself a finding: `providers` is gated
on that feature, so a plain `cargo test -p epsilon-llm` collects 71 tests and
silently omits the entire provider-stream surface, 109 in total. See
"Collateral finding" below.)

Expected failure
----------------
    providers::http_stream_tests::every_frame_in_one_chunk_is_delivered_not_just_the_first
    assertion `left == right` failed: every frame in a single chunk must reach the
    consumer, in order
      left: "one "
     right: "one two three"

Observed
--------
    CONTROL_EXIT=101
    test providers::http_stream_tests::every_frame_in_one_chunk_is_delivered_not_just_the_first ... FAILED
    test providers::http_stream_tests::one_frame_per_chunk_gives_the_same_answer_as_one_big_chunk ... ok
    test providers::http_stream_tests::a_frame_split_mid_line_still_reassembles ... ok
    test result: FAILED. 4 passed; 1 failed; 0 ignored; 0 measured; 104 filtered out

Reading the result
------------------
The consumer received `"one "` and nothing else. Two of the three frames were gone,
with no error, no warning, and a terminal `Done`. That is the whole harm of F03: a
harness that confidently reports a two-thirds answer as the model's complete reply.

Note which tests did NOT fail, and why that is the point:

  - `one_frame_per_chunk_gives_the_same_answer_as_one_big_chunk` passes under the
    control because the control only misbehaves when a chunk contains more than one
    frame. A fix that had merely broken the single-chunk path would be caught here.
  - `a_frame_split_mid_line_still_reassembles` passes because line reassembly is
    untouched by the control. It guards the opposite failure — a "fix" that dropped
    `line_buf` entirely would fail here.

Restoration
-----------
The control insertion was removed and the two lines restored to:

    // Queue the whole batch, keep going. Returning here is the bug.
    self.queued.extend(batch);

    $ cargo test -p epsilon-llm --features real --lib http_stream
    EXIT=0
    test result: ok. 5 passed; 0 failed; 0 ignored; 0 measured; 104 filtered out

    $ cargo fmt --all -- --check
    FMT_AFTER=0

The final battery (`m137`) was run against these restored bytes.

Collateral finding — 38 provider tests were never being run
-----------------------------------------------------------
While building the control I found that `cargo test -p epsilon-llm` (no feature
flag) collects 71 tests, and with `--features real` it collects 109. The 38 missing
tests are the whole `providers::http_stream_tests` module plus the per-provider
codec tests, because `crates/epsilon-llm/src/lib.rs` gates `pub mod providers` on
`#[cfg(feature = "real")]`.

`real` IS a default feature (since M63), so the workspace battery runs them. But
any per-crate invocation without the flag silently drops a third of the crate's
tests and still reports "test result: ok". That is a trap, not a bug, and it is
recorded here because the three new F03 tests would have been dead code under a
`cargo test -p epsilon-llm` habit. M137's own evidence always passes `--features
real` explicitly.

The pre-existing `deepseek_text_chunk_produces_done_with_nonempty_content` and
`deepseek_wire_synthesizes_start_before_text` tests are part of that previously
uncollected set; both pass.
