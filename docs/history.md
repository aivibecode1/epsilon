# Project history

Epsilon grew milestone by milestone. Each one landed as a single commit with a
dev log under [`milestones/`](milestones) and an entry in the root
[`CHANGELOG.md`](../CHANGELOG.md). This file holds the timeline and the
reference tables that used to bloat the README: what shipped when, the original
acceptance criteria, and the decision-log index.

| M70 | **Message sanitization** — three shapes a model produces that used to cost the harness its intent. (1) Tool-call arguments that are not valid JSON were replaced with `{}` (`from_str(..).unwrap_or_else(|_| json!({}))`), so the tool ran with no arguments and the model was told it forgot a field; `epsilon-llm/src/sanitize.rs` now recovers a trailing comma, a payload cut off by the output limit, a double-encoded string and unambiguous single quotes — and hands an unreadable payload on verbatim so the failure quotes it. | M71 | **The edit matcher's loose end** — every harness hits it: the model knows what to change and the tool refuses because the quoted text does not byte-match. The chain had three stages and no bound on how much a loose stage could match. `epsilon-tools/src/edit_match.rs` now runs six stages, ordered by rising risk so a file containing the text verbatim is never "found approximately" elsewhere first: exact, line-trimmed, indentation-flexible, escape-normalized (`\n` written as literal text), trimmed-boundary (blank lines the file lacks), and block-anchor (first/last lines matched at ≥0.65 similarity, the region between replaced). The block-anchor stage is the only one that can match a different height than `old_string`, so it is the only one the refusal can fire on: a span of `max(old+3, old*2)` lines or +500 characters is refused with the numbers and guidance instead of applied, which meant a percentage-of-file rule was rejected (it would refuse a legitimate 40-line edit in a 100-line file). Batch edits stay exact-only; their not-found message now says to send that edit alone for the fuzzy stages. 650 tests. |
| M72 | **The batch planner** — the ordering rule was all-or-nothing: one `Sequential` tool anywhere in a batch made the whole batch a barrier, and since `write`/`edit` are `Sequential`, three edits to three different files ran one at a time — the most common batch a coding agent produces, paying for itself in seconds. Tools now declare a `resource_key` (`Tool::resource_key`, resolved against the same cwd execution receives), and `exec::plan_batch` groups a batch by conflict: paths that are prefixed by one another are one resource (a `grep` over `src/` does not run beside a `write` to `src/lib.rs`), two readers never conflict (so workspace-wide searches stay concurrent), and one resource means one chain in call order — built by union-find rather than greedy bin-packing, which would have run a third same-file call beside the first. `bash`/`task` declare nothing, so their unknown reach still barriers the batch; blocked calls no longer serialize anything they do not execute. 662 tests. |

| M75 | **Typed corruption reasons** — every unusable session line was reported as `corrupt session line #5`, which merged two unrelated situations: the line really is damaged, and the line is perfectly valid but was written by a *newer* Epsilon carrying an entry kind this build has never seen. | M77 | **Sandbox truthfulness** — `Sandbox::run` reported an exit code and nothing about the *quality* of the confinement, which left the real Windows caveat (job objects bound memory, process count and CPU, and restrict nothing about what a process reads or writes) as a paragraph in an audit report — not something a caller can check, and free to drift from what the sandbox actually does. `Enforcement { Full, Partial { missing } }` now rides on every `ConfinedOutcome`, `Sandbox::capabilities()` makes each backend declare its own envelope (Windows: `filesystem, network`; bubblewrap: `memory, process tree, wall clock`; null: everything), and `epsilon doctor` prints that declaration rather than a `cfg` string in its source. One- and two-character queries drew a frame in time; five or six left the composer showing its *placeholder*, which is indistinguishable from a hang and is the same symptom class the owner originally reported. The probe ruled out timing by repeating the failure at four waits, and a `--at SECONDS` option now exists so the next such question is measurable. Fixed twice over, because the two halves fix different things: the frontend caches the rules with a five-second TTL, and the matcher prunes ignored directories — git's own rule, since a `.gitignore` inside an ignored tree can only speak about paths git would never look at — which makes `grep`/`find`/`read` cheaper too. Landed 85503a6. |
| M111 | **The cost estimate prices what it was leaving out** — the header's cost figure added up two of the four **disjoint** token buckets a provider reports: `usage.input` excludes cached tokens by the adapters' own split, so cache reads and cache writes were charged at zero and a cache-heavy session's estimate was low by roughly the cached share times the input price. The fix is not arithmetic: `ModelInfo` gains both cache prices, sourced by the generator from models.dev (359 of 557 rows publish a read price, 114 a write price), and the bundled catalog was regenerated — disclosed in the commit as a week of upstream drift as well (547 rows → 557, 15 in, 5 out, some prices moved, the generation pins unmoved). `0` means *not published*, which is not the same as free, so a session that moved tokens the registry cannot price reports a **floor** — `.42+` — instead of a precise-looking total that silently omits real tokens. The arithmetic moved out of the draw path into `ui/cost.rs` with four tests, including the one the old code failed and one for the four-truncations rounding that could zero a sub-cent session. Landed fbe6d96. |
| M112 | **The cost model gets a shape, its dead twin leaves, and the header gets a legend** — `CostBreakdown` now carries the four components with the unscaled products private so `total()` sums them and divides **once**; a first attempt at the refactor divided each part and two half-micro-USD components totalled to zero, which is the bug M111 had just fixed — the round's own test caught it. The floor rule narrowed: it now requires that the registry prices the model *somewhere* before a zero bucket counts as a gap, because every rate zero means free or local and those sessions would have printed `\+` for something that genuinely cost nothing. The dead `CostMicro` type (a second per-rate cost type with an `Add` impl, constructed by nothing) left `epsilon-contracts` — M107's class of dead code, in the crate whose rule is types-and-traits-only. And `/help` finally decodes the header: the `?`, the `—`, the arrows and the `+` were documented in code and nowhere a user would look. Landed cc25f5b. |
| M113 | **An entry kind this build does not know is kept, not used to close the session** — a session file carrying a `kind.type` from a newer build was **refused whole**: one foreign entry cost the entire conversation, and the only routes back were to upgrade or edit the file by hand. The refusal came from M108, whose reason was sound — a complete line written on purpose must not be deleted — but whose remedy was the most destructive of the safe options. An entry can instead be *kept*: parsed as an opaque object, replayed on the next write, left out of the model view. That honours "do not delete" *and* leaves the session usable. The rule is **lenient about the tag, strict about the body** — a *known* kind with an unreadable body is still refused, because preserving that would open the session with a silent gap where a turn should be — and the two cases get two diagnoses (`UnknownEntryType` "foreign" versus the new `MalformedEntry` "damaged"), which also closes the item M108's own Limits recorded as owed. `KNOWN_ENTRY_KINDS` is one exported list with a drift guard, and `preserved_unknown()` lets a frontend report what it kept. Verified end to end: a real session plus one foreign entry went from exit 1 with a refusal to exit 0 with two entries resumed and the file byte-identical. Landed 689794e. |
| M114 | **The healer that read pi's messages and emptied them** — `heal_legacy_line` converts pi's pre-v2 entries into this build's format, and it emptied every message it touched: `message.content` was read with `as_str()` while pi writes an **array of parts**, so `unwrap_or("")` produced an empty message; `message.role` was ignored, so every role became a *user* turn; and `timestamp` was read as a number while pi writes an ISO string, so every entry was re-dated to the moment of the import. Found by **running** it — `epsilon --resume before-compaction.jsonl --print hi` reported "resumed 369 entries", exit 0, and turned a 668-character prompt into nothing, which made the port's headline interop claim worse than a refusal because it succeeded silently. The fix maps all four of pi's roles (assistant faithfully: provider, model, stopReason, usage, errorMessage), converts the content array part by part, preserves anything it cannot type rather than dropping it, and prefers the finer of pi's two timestamp spellings — the ISO parse being hand-written so no dependency is added. Verified on pi's own fixture: the prompt comes back whole. Landed d54dfb8. |
