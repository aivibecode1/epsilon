# Project history

Epsilon grew milestone by milestone. Each one landed as a single commit with a
dev log under [`milestones/`](milestones) and an entry in the root
[`CHANGELOG.md`](../CHANGELOG.md). This file holds the timeline and the
reference tables that used to bloat the README: what shipped when, the original
acceptance criteria, and the decision-log index.

| M65 | **The stale-read guard** — `write`/`edit` are the only tools that can destroy work, and nothing until now checked that the model's picture of a file still matched the disk (a `task` child, a background script or the user's editor all write to the same files). Reads are now recorded per path (mtime + size + whether the view was partial, and why) and mutations are verified against them inside the per-path queue: overwriting an existing file that was never read, writing or editing a file that changed since the last read, and overwriting wholesale a file that was only read in part are each refused with the path, the reason and the action that lifts it — while a window the harness's own 256 KB read cap imposed is exempt, since no re-read could widen it. The cap itself stopped being silent: the read result now reports the file's size and that the rest was not sent. Registry is process-global, so a `task` child's read and the parent's write are checked against each other. 12 new tests (8 unit + 4 driving the real tools); with the guard short-circuited 8 of them fail. | M67 | **Stuck-run guards** — the brakes counted identical *calls*, which a stuck run rarely produces. `epsilon-core/src/guards.rs` signatures each tool RESULT (error-ness + a normalized 200-char head) and counts consecutive identical ones: at `no_progress_threshold` (default 3) the guidance rides along with the result the model reads, escalating at twice the threshold, and a stalled run raises a `no_progress` permission request (once per batch) on the same surface as the doom-loop brake. | M68 | **Verification evidence + stop-time nudge** — the contract tells the model to run the project's checks after editing and nothing recorded whether it did. `epsilon-core/src/verify.rs` logs every successful `write`/`edit` with its turn and every check-like `bash` command with its exit status (known runner + check sub-command, a program that *is* the check, or one inside a compound command — `grep -r test .` and `cargo fmt` are not checks), and a file counts as unverified when no PASSING check has run since it was last changed. | M69 | **Cache attribution** — a hit-rate percentage cannot say why it dropped. `epsilon-core/src/cache_stats.rs` classifies every provider call as cold (first of the process), served, or re-billed with a named cause: model switch, a prompt prefix that stopped being byte-stable (via the new `prompt::stable_fingerprint`, which hashes the STABLE tier alone so a changing date or cwd is not mistaken for a cache break), an idle gap past the TTL, or nothing the harness can see — a provider that reports no cache traffic is described as silent, never as wasteful. | M70 | **Message sanitization** — three shapes a model produces that used to cost the harness its intent. (1) Tool-call arguments that are not valid JSON were replaced with `{}` (`from_str(..).unwrap_or_else(|_| json!({}))`), so the tool ran with no arguments and the model was told it forgot a field; `epsilon-llm/src/sanitize.rs` now recovers a trailing comma, a payload cut off by the output limit, a double-encoded string and unambiguous single quotes — and hands an unreadable payload on verbatim so the failure quotes it. A repair that would recover nothing is refused, because an empty success is the old bug wearing a repair's clothes. (2) Duplicate tool-call ids in one message are renamed deterministically (`<id>#2`) — providers reject them and the result pairing was ambiguous. (3) A run aborted between a tool call and its result left a transcript that providers reject on the *next* request; `Agent::close_dangling_tool_calls` now answers every unanswered call with an error result that says it was never executed. `basic_validate` names what arrived (bounded). 637 tests. |
| M71 | **The edit matcher's loose end** — every harness hits it: the model knows what to change and the tool refuses because the quoted text does not byte-match. The chain had three stages and no bound on how much a loose stage could match. `epsilon-tools/src/edit_match.rs` now runs six stages, ordered by rising risk so a file containing the text verbatim is never "found approximately" elsewhere first: exact, line-trimmed, indentation-flexible, escape-normalized (`\n` written as literal text), trimmed-boundary (blank lines the file lacks), and block-anchor (first/last lines matched at ≥0.65 similarity, the region between replaced). The block-anchor stage is the only one that can match a different height than `old_string`, so it is the only one the refusal can fire on: a span of `max(old+3, old*2)` lines or +500 characters is refused with the numbers and guidance instead of applied, which meant a percentage-of-file rule was rejected (it would refuse a legitimate 40-line edit in a 100-line file). Batch edits stay exact-only; their not-found message now says to send that edit alone for the fuzzy stages. 650 tests. |
| M72 | **The batch planner** — the ordering rule was all-or-nothing: one `Sequential` tool anywhere in a batch made the whole batch a barrier, and since `write`/`edit` are `Sequential`, three edits to three different files ran one at a time — the most common batch a coding agent produces, paying for itself in seconds. Tools now declare a `resource_key` (`Tool::resource_key`, resolved against the same cwd execution receives), and `exec::plan_batch` groups a batch by conflict: paths that are prefixed by one another are one resource (a `grep` over `src/` does not run beside a `write` to `src/lib.rs`), two readers never conflict (so workspace-wide searches stay concurrent), and one resource means one chain in call order — built by union-find rather than greedy bin-packing, which would have run a third same-file call beside the first. `bash`/`task` declare nothing, so their unknown reach still barriers the batch; blocked calls no longer serialize anything they do not execute. 662 tests. |
| M73 | **Subdirectory hints** — only the workspace-root `AGENTS.md`/`CLAUDE.md` reached the model, so in a monorepo (this one included: every crate has its own rules) the model working in `crates/x/` guessed at conventions written down one directory away — a quiet failure, nothing errors, the work is just slightly wrong. `Agent::note_touched` now records the directory of every validated call (reusing M72's declared resource, so nothing is re-parsed and the planner cannot disagree with where the call went) and `prompt::load_subdirectory_hints` loads the family from those directories and their ancestors into the CONTEXT tier with every bound explicit: ≤5 levels up, the root excluded (already loaded), deduped by content digest, ≤5 files nearest-first, 4 KB each with the cut announced rather than silent. | M75 | **Typed corruption reasons** — every unusable session line was reported as `corrupt session line #5`, which merged two unrelated situations: the line really is damaged, and the line is perfectly valid but was written by a *newer* Epsilon carrying an entry kind this build has never seen. The second is version skew, and telling a user their session is corrupt sends them looking for a fault that is not there — and makes deleting a healthy session look like the fix. `LineDiagnosis` now separates them (`NotJson`, `UnknownEntryType` — refused with the type quoted, `SecondHeader`, `LegacyInCurrentFile`) and `Display` explains the cause and the consequence. Repairs report *kinds* rather than counts (`RepairKind::{DanglingToolCall, MissingTurnEnd}`, the two shapes this harness can actually produce — pi's twelve describe a reducer with more states, and a reason that cannot occur is a claim nobody can test), the synthesized result carries `details.repair`, and `/session` prints what a resumed session was missing. A torn *last* line stays tolerated: a partial write is expected, mid-file damage is not. This closes plan item 13 and with it Tier 3. 694 tests. |
| M76 | **`epsilon doctor`** — the audit's own headline finding was that the engine was complete and the on-ramp was missing: a user could install the binary, watch it reach no model, and have no way to learn why. `epsilon-cli/src/doctor.rs` prints one diagnosis — build (and whether the binary can reach a network at all), the resolved model with *how* it was resolved and *where* the credential comes from (presence and source, never a value), the sandbox backend the platform actually provides, the workspace's instructions/trust/MCP, the session file with its lease holder, the built-in tool list, and the last failures from the newest session — and exits non-zero when a blocker is found, naming the command that fixes each. It runs before the runtime is built, so it cannot fail on the thing it diagnoses and takes no lease. In this repository it reproduces the trap exactly: a saved `deepseek-chat` resolves by substring to OpenRouter's row with no credential while a `deepseek` key sits unused. 713 tests. |
| M77 | **Sandbox truthfulness** — `Sandbox::run` reported an exit code and nothing about the *quality* of the confinement, which left the real Windows caveat (job objects bound memory, process count and CPU, and restrict nothing about what a process reads or writes) as a paragraph in an audit report — not something a caller can check, and free to drift from what the sandbox actually does. `Enforcement { Full, Partial { missing } }` now rides on every `ConfinedOutcome`, `Sandbox::capabilities()` makes each backend declare its own envelope (Windows: `filesystem, network`; bubblewrap: `memory, process tree, wall clock`; null: everything), and `epsilon doctor` prints that declaration rather than a `cfg` string in its source. The cut is on a **character** boundary, asserted with Japanese text, so a row never ends in the replacement character a byte slice leaves behind. Applied to the task description, its detail line, the session name and the count line; **not** to the transcript, which wraps and shows that it wraps, nor to the editor, whose monospaced gutter makes a cut column obvious. GATE PASS `m247` on attempt 1, 1,794 tests / 74 binaries. |
