# Project history

Epsilon grew milestone by milestone. Each one landed as a single commit with a
dev log under [`milestones/`](milestones) and an entry in the root
[`CHANGELOG.md`](../CHANGELOG.md). This file holds the timeline and the
reference tables that used to bloat the README: what shipped when, the original
acceptance criteria, and the decision-log index.

| M70 | **Message sanitization** — three shapes a model produces that used to cost the harness its intent. (1) Tool-call arguments that are not valid JSON were replaced with `{}` (`from_str(..).unwrap_or_else(|_| json!({}))`), so the tool ran with no arguments and the model was told it forgot a field; `epsilon-llm/src/sanitize.rs` now recovers a trailing comma, a payload cut off by the output limit, a double-encoded string and unambiguous single quotes — and hands an unreadable payload on verbatim so the failure quotes it. | M71 | **The edit matcher's loose end** — every harness hits it: the model knows what to change and the tool refuses because the quoted text does not byte-match. The chain had three stages and no bound on how much a loose stage could match. `epsilon-tools/src/edit_match.rs` now runs six stages, ordered by rising risk so a file containing the text verbatim is never "found approximately" elsewhere first: exact, line-trimmed, indentation-flexible, escape-normalized (`\n` written as literal text), trimmed-boundary (blank lines the file lacks), and block-anchor (first/last lines matched at ≥0.65 similarity, the region between replaced). The block-anchor stage is the only one that can match a different height than `old_string`, so it is the only one the refusal can fire on: a span of `max(old+3, old*2)` lines or +500 characters is refused with the numbers and guidance instead of applied, which meant a percentage-of-file rule was rejected (it would refuse a legitimate 40-line edit in a 100-line file). Batch edits stay exact-only; their not-found message now says to send that edit alone for the fuzzy stages. 650 tests. |
| M72 | **The batch planner** — the ordering rule was all-or-nothing: one `Sequential` tool anywhere in a batch made the whole batch a barrier, and since `write`/`edit` are `Sequential`, three edits to three different files ran one at a time — the most common batch a coding agent produces, paying for itself in seconds. Tools now declare a `resource_key` (`Tool::resource_key`, resolved against the same cwd execution receives), and `exec::plan_batch` groups a batch by conflict: paths that are prefixed by one another are one resource (a `grep` over `src/` does not run beside a `write` to `src/lib.rs`), two readers never conflict (so workspace-wide searches stay concurrent), and one resource means one chain in call order — built by union-find rather than greedy bin-packing, which would have run a third same-file call beside the first. `bash`/`task` declare nothing, so their unknown reach still barriers the batch; blocked calls no longer serialize anything they do not execute. 662 tests. |

| M75 | **Typed corruption reasons** — every unusable session line was reported as `corrupt session line #5`, which merged two unrelated situations: the line really is damaged, and the line is perfectly valid but was written by a *newer* Epsilon carrying an entry kind this build has never seen. | M77 | **Sandbox truthfulness** — `Sandbox::run` reported an exit code and nothing about the *quality* of the confinement, which left the real Windows caveat (job objects bound memory, process count and CPU, and restrict nothing about what a process reads or writes) as a paragraph in an audit report — not something a caller can check, and free to drift from what the sandbox actually does. `Enforcement { Full, Partial { missing } }` now rides on every `ConfinedOutcome`, `Sandbox::capabilities()` makes each backend declare its own envelope (Windows: `filesystem, network`; bubblewrap: `memory, process tree, wall clock`; null: everything), and `epsilon doctor` prints that declaration rather than a `cfg` string in its source. Porting item 14 also exposed a real gap: the bubblewrap backend accepts the policy's wall-clock limit and ignores it; declared in its capabilities and recorded as open, because fixing it needs a Linux run to verify. 723 tests. |
| M78 | **Per-call sandbox modes** — `bwrap_argv` mounted the workspace writable unconditionally, so a review task that only reads had no way to say so and no way to have it enforced: one policy per registry, a session-wide `--sandbox auto|off`, nothing in between. The three-rung ladder now exists (`read-only` / `workspace-write` / `danger-full-access`) with a strictly-wider table, per-call resolution into `ConfinedCommand`, a read-only workspace mount on Unix, and both backends refusing `danger-full-access` rather than calling their own limits full access. A call may always *narrow* itself (asking for less needs no approval, and `--sandbox read-only` starts a session on that rung); asking *wider* is refused with the reason and the hint, and the escape hatch stays where a human put it. The paired `sandbox_permissions`/`justification` arguments are validated because a schema cannot express "these two travel together". Six mutations, six failing tests. The approval ask for a widening is recorded as open — a per-call consent grant needs a harness-owned channel, and borrowing the model's own arguments would be forgeable. |
| M79 | **LSP diagnostics as edit feedback** — every edit was made blind: the model wrote code, the compiler disagreed a turn later or never. A twelfth crate (`epsilon-lsp`: framing, server table, client, service, report) behind a `DiagnosticsProvider` seam in contracts now asks the language server and rides a bounded block on the edit's own output — errors only, ≤20 per file, `ERROR [line:col] message`. One client per (project root, server), the spawn dedupe guaranteed by holding the map lock rather than hoped for, and a `broken` set so a server that refuses to handshake is not respawned per edit. Servers are user-installed only (no download paths, unlike opencode) and degradation is silent at every failure point, because failing an edit for want of a linter is worse than not linting. Six mutations, six discriminations, and the end-to-end tests drive a real LSP child process. |
| M81 | **Observation ownership** — a read authorized a write for any agent in the session: the shared read-log let agent B edit a file it never read because agent A had. Each agent now owns an opaque observation token; task children and restored sessions get fresh ones, sibling writes invalidate the cached observation even when mtime and length still match, and a failed edit no longer refreshes what the next attempt is verified against. Weak references reclaim retired scopes; per-path mutation queues stay shared. Closes F02. |
| M82 | **Plan-mode enforcement** — `--plan` denied `git commit*` patterns that core never matched (it authorizes the command head only) and *replaced* project rules, so a project read-deny evaporated and bash ran unimpeded. The plan ruleset now denies `bash`/`shell` outright (string prefixes cannot establish a read-only shell boundary), `--plan` layers the plan ruleset over project rules instead of replacing them (ADR-006), and authorization is additive end to end: the original tool capability is checked first, a path-derived `external_dir` subject can only add a constraint, and either denial short-circuits — so a `dir:` argument can no longer mask a plan deny on shell. Closes F10. |
| M83 | **Baseline dependency integration** — forward completion of missing companion sources, with partial-file exclusions and an isolated candidate verified by all five gates plus locked real/offline checks. 740 tests passed, 0 failed; broader owner changes remain uncommitted. Existing audit risks are not closed by source integration. |

| M84 | **Find directory resource** — shared search key repairs directory-reader/descendant-writer scheduling. Red/green regression; isolated five-gate repeat passed 741 tests. Initial auth-lock failure retained; F09 containment remains open. |
| M85 | **Follow-up default** — queued follow-ups now deliver one at a time (pi constructor parity); explicit All batching preserved. Isolated five-gate candidate: 742 passed, 0 failed; independent review passed. Explicit-mode breadth, event/tool-cycle coverage and callback/session gaps remain open. |
| M86 | **Compaction correctness** — a second compaction left the *superseded* projection in the model view: `SessionStore::model_view` appended each new summary+tail to the previous one instead of replacing it, so the provider saw both the new summary and the summary it had just replaced (pi keeps the latest compaction on the active path, `session-manager.ts:426-451`). Commit now happens in one region with no await between the final checks and the swap — non-failure stop reason, usable text, successful durable append — and an empty or whitespace-only summary is never folded in (`summary_text` returns `Option<String>`; the placeholder template is gone). Failures arrive as a `Notice`; a poisoned history after a successful append pops the entry again rather than splitting the two views; a cancelled run that salvaged a partial answer commits its terminal message to history and the store like a completed turn. 751 tests. |
| M87 | **Admission that reflects reality** — the RPC loop answered `{"started": true}` for every prompt, including the ones the agent refused a moment later with `AlreadyRunning` (the guard was a helper that always returned false), and the HTTP server checked a run counter and spawned in two separate steps, so overlapping requests could both be told they had started. `admit_prompt` now races the spawned run against its own first event and answers with what actually happened; the select is biased to the event arm so a run that was admitted and then failed is never reported as "no work started" — that reply would invite a retry that double-prompts — and subscribing before the spawn closes the window where `AgentStart` could beat the listener into existence. Serve reserves its slot atomically (`fetch_add` *is* the decision; the release guard is built immediately after the reservation) and logs in-band refusals instead of discarding them. 751 tests. |
| M88 | **Mid-batch abort** — Esc cancelled the stream but not the schedule: `execute_batch` never consulted the run token between calls, so every remaining call in a batch started and ran to completion after the user had stopped the turn (pi stops scheduling and marks the remainder "Operation aborted", `agent-loop.ts:478-553`). `run_one` now checks the token before executing and refuses a call that never started with the aborted-result shape ("not executed: the run was cancelled before it started", `details.aborted`) — one checkpoint covering both the serial and the barrier plan. 751 tests. |
