# Project history

Epsilon grew milestone by milestone. Each one landed as a single commit with a
dev log under [`milestones/`](milestones) and an entry in the root
[`CHANGELOG.md`](../CHANGELOG.md). This file holds the timeline and the
reference tables that used to bloat the README: what shipped when, the original
acceptance criteria, and the decision-log index.

| M70 | **Message sanitization** — three shapes a model produces that used to cost the harness its intent. (1) Tool-call arguments that are not valid JSON were replaced with `{}` (`from_str(..).unwrap_or_else(|_| json!({}))`), so the tool ran with no arguments and the model was told it forgot a field; `epsilon-llm/src/sanitize.rs` now recovers a trailing comma, a payload cut off by the output limit, a double-encoded string and unambiguous single quotes — and hands an unreadable payload on verbatim so the failure quotes it. | M71 | **The edit matcher's loose end** — every harness hits it: the model knows what to change and the tool refuses because the quoted text does not byte-match. The chain had three stages and no bound on how much a loose stage could match. `epsilon-tools/src/edit_match.rs` now runs six stages, ordered by rising risk so a file containing the text verbatim is never "found approximately" elsewhere first: exact, line-trimmed, indentation-flexible, escape-normalized (`\n` written as literal text), trimmed-boundary (blank lines the file lacks), and block-anchor (first/last lines matched at ≥0.65 similarity, the region between replaced). The block-anchor stage is the only one that can match a different height than `old_string`, so it is the only one the refusal can fire on: a span of `max(old+3, old*2)` lines or +500 characters is refused with the numbers and guidance instead of applied, which meant a percentage-of-file rule was rejected (it would refuse a legitimate 40-line edit in a 100-line file). Batch edits stay exact-only; their not-found message now says to send that edit alone for the fuzzy stages. 650 tests. |
| M72 | **The batch planner** — the ordering rule was all-or-nothing: one `Sequential` tool anywhere in a batch made the whole batch a barrier, and since `write`/`edit` are `Sequential`, three edits to three different files ran one at a time — the most common batch a coding agent produces, paying for itself in seconds. Tools now declare a `resource_key` (`Tool::resource_key`, resolved against the same cwd execution receives), and `exec::plan_batch` groups a batch by conflict: paths that are prefixed by one another are one resource (a `grep` over `src/` does not run beside a `write` to `src/lib.rs`), two readers never conflict (so workspace-wide searches stay concurrent), and one resource means one chain in call order — built by union-find rather than greedy bin-packing, which would have run a third same-file call beside the first. `bash`/`task` declare nothing, so their unknown reach still barriers the batch; blocked calls no longer serialize anything they do not execute. 662 tests. |

| M75 | **Typed corruption reasons** — every unusable session line was reported as `corrupt session line #5`, which merged two unrelated situations: the line really is damaged, and the line is perfectly valid but was written by a *newer* Epsilon carrying an entry kind this build has never seen. | M77 | **Sandbox truthfulness** — `Sandbox::run` reported an exit code and nothing about the *quality* of the confinement, which left the real Windows caveat (job objects bound memory, process count and CPU, and restrict nothing about what a process reads or writes) as a paragraph in an audit report — not something a caller can check, and free to drift from what the sandbox actually does. `Enforcement { Full, Partial { missing } }` now rides on every `ConfinedOutcome`, `Sandbox::capabilities()` makes each backend declare its own envelope (Windows: `filesystem, network`; bubblewrap: `memory, process tree, wall clock`; null: everything), and `epsilon doctor` prints that declaration rather than a `cfg` string in its source.
