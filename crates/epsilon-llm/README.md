# epsilon-llm

## What this crate is

The multi-provider LLM layer, behind one never-failing trait. Every provider — a real HTTP
adapter or an offline script — implements `StreamFn`, which returns a stream of
`StreamEvent`s whose terminal event carries success or failure as data. It owns routing,
the model catalog, credential storage, retry and pacing. It does not own the agent loop,
the tools or the permission decision.

## How it connects

- **Depends on:** `epsilon-contracts` only.
- **Depended on by:** `epsilon-core`, and through it `epsilon-runtime`, `epsilon-tui`,
  `epsilon-server`, `epsilon-cli`. `epsilon-safety` depends on it for
  its tests only.

## Entry points

- `stream_fn` — the contract: `StreamFn` (`src/stream_fn.rs:63`), `LlmContext` (`:28`),
  `EventStream` (`:45`), `BoxEventStream` (`:51`), `ModelRef` (`:13`), and `PanicGuard`
  (`:70`), the blanket wrapper that turns a panicking provider into a failed stream.
- `faux` — `FauxProvider` (`src/faux.rs:80`) and `FauxStep` (`:22`), the scripted offline
  provider every full-loop test runs against.
- `catalog` — `ModelInfo` (`src/catalog.rs:119`) and the resolution chain:
  `resolve_model_for_run` (`:443`), `resolve_model` (`:231`), `lookup_model` (`:188`),
  `resolve_api_key` (`:504`).
- `auth` — credential storage: `StoredCredential` (`src/auth.rs:49`), `save_credential`
  (`:793`), `load_credentials` (`:786`), `sign_bedrock_request` (`:417`).
- `retry` / `retry_stream` — `classify` (`src/retry.rs:27`), `should_retry` (`:72`),
  `Retrying` (`src/retry_stream.rs:48`), `RetryNotice` (`:31`).
- `providers` (`real` only) — `ProviderWire` (`src/providers/mod.rs:52`) and one module
  per family: `anthropic`, `bedrock`, `google`, `vertex`, `github_copilot`, `mistral`,
  `openai_compat`, `openai_responses`. Also `oauth` and `oauth_login` (PKCE and
  device-code logins), `custom` (user-declared providers), `cache_policy`, `fallback`
  (`real`), `paced`, `sanitize`.

## How to run and test it

No binary of its own — a caller supplies a `StreamFn` to the loop.

```sh
cargo check -p epsilon-llm
cargo test -p epsilon-llm
```

## Things worth knowing

- The `real` feature is **off by default**: `providers`, `fallback` and the `reqwest` /
  `rustls` dependencies do not exist in a default build. `epsilon-core` and
  `epsilon-runtime` forward to it with `real = ["epsilon-llm/real"]`, so a default
  workspace build has it on and a bare `cargo test -p epsilon-llm` does not.
  `tests/usage_arithmetic.rs` declares `required-features = ["real"]` because it
  exercises `providers::test_support`; without the feature it cannot even compile.
- `catalog/catalog_data.rs` is generated by `scripts/regen_catalog.py` from models.dev.
  Do not hand-edit it. Routing reads `ModelInfo::wire`; behaviour selection reads
  capability fields, and nothing string-matches model-family names (`src/catalog.rs:14`).
- Credentials live in `<global_dir>/auth.json`. Every write takes a cross-process lock,
  persists through a same-directory temp file plus rename, sets 0600 on unix, and refuses
  to overwrite a corrupt file (`src/auth.rs:14`).
- `PanicGuard` enforces the trait's "must not panic" rule mechanically — wrap a raw
  provider in it before handing it to the loop (`src/stream_fn.rs:68`). `RETRY_MAX_ATTEMPTS`
  is 5 (`src/lib.rs:55`) and `backoff_delay` caps at 30 s (`src/retry.rs:102`).
