Make precise edits to an existing file. Prefer the batch form edits:[{old_string,new_string}...] when touching multiple disjoint regions in one call — each old_string is matched against the original file (not incrementally) and must be unique and non-overlapping; merge nearby changes into one entry. The single-edit form old_string+new_string remains for one hunk; old_string must match exactly once unless replace_all is set. All matching is exact after LF normalization; on miss you get the closest matching line as a hint. An edit is refused if the file changed on disk since it was last read: read it again, then retry. Single and batch edits require a complete, valid UTF-8 source no larger than 262144 bytes (256 KiB); larger or invalid-UTF-8 files are refused without writing. A partial read does not bypass this edit limit.
