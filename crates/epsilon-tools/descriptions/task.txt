Delegate a focused subtask to a subagent. Use for independent work that can run with its own context — e.g. exploring one area of the codebase, drafting one file, or researching one question. Provide a complete prompt with all necessary context because the subagent starts fresh and does not see your current conversation. Keep the description to 3-5 words and make the prompt highly detailed, including exactly what to return. Prefer running independent subtasks in parallel via one tool batch when the work does not overlap on files.

Cost: pass model to run the child on a specific catalog model (e.g. `deepseek-flash`) — useful for wide-context scouting, mechanical sweeps, or any work where a cheap model is enough, while you keep the session's own model for the hard parts. Omit it to inherit this session's model (an agent type that defines its own model wins over this parameter). The result tells you which model actually ran, so never assume — if you need a specific one and the result names another, say so instead of silently continuing.

Long jobs: set background=true to start the child and get its task id back immediately; its result arrives later as its own message, and you can keep working in the meantime. Address a task you already started by passing its task_id — with a prompt it continues that same child (it remembers its earlier turns), with no prompt it just reports the task's current state and output. Use task_id when a follow-up belongs to the same investigation instead of re-explaining everything to a fresh child — a child outlives the process that started it (its transcript is kept on disk), so a task_id from earlier still resumes. Resuming keeps the child's model; model applies when a task starts.
